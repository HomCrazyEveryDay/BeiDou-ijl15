# 原生 Buff 倒计时绘制

本次针对“Buff 图标隐藏后，黄绿数字仍留在右上角”的问题，将数字从 D3D8 EndScene 覆盖层迁入原生 Buff 阴影画布。服务端属性叠加、药水取最大值和原有补图标协议均不变；额外同步倍率券的实际剩余时间，并修复其登录/死亡恢复。快捷栏冷却显示不在本次范围。

参考：[GMS 现代化实时倒计时显示](https://moguwuyu.com/d/117-gms现代化实时倒计时显示buff持续时间和快捷栏冷却时间)。使用公开的原生阴影更新思路，未复制登录后可见的代码；帖子地址为 v92，本地地址依据当前 BeiDou.exe（v83）重新核对。

## 显示行为

- 剩余时间 >= 60 秒：左下角显示向上取整的分钟数，支持一小时以上的有限时长。
- 剩余时间 < 60 秒：中央显示向上取整的秒数，使用原生像素字体大小。
- 弓手专注：右下角显示 1–5 层，优先于时间。
- 无期限、非正剩余时间：不显示时间数字。
- 双倍经验/掉率券（`5211xxx`、`5360xxx`）保留原生图标；倒计时取服务端背包物品的实际到期时间。永久券保留图标但不显示数字。WZ 的 `time=2147483647` 占位值不会作为分钟数显示。
- 复用现有 UI/Basic.img/ItemNo 数字，白色描边字形。没有添加 UIWindow99.img，也不需要 XML/IMG 同步。
- 数字与阴影合成后由原生图层持有；坐标、显隐、alpha、闪烁和销毁由原生流程管理。没有独立屏幕坐标绘制路径。

## v83 接入与资源所有权

| 接入点 | 地址/偏移 | 依据 |
|---|---|---|
| TEMPORARY_STAT 阴影更新 | 0x007B44F4 | +38 剩余时间除以 +3C 阴影帧间隔，限制为 0–15，与 +30 比较 |
| 阴影画布插入调用点 | 0x007B4748 | 调用 0x00426BAB；只重定向这一处 CALL |
| 阴影层 | entry +0x2C | 原生移除旧画布并插入资源画布的接收对象 |
| 原生禁用阴影标记 | entry +0x34 | 原函数在该值非零时直接返回 |
| 资源管理器 | 0x00BF14E8 | 原生资源访问 getter 与 GetObject 包装函数 |
| PCOM factory | 0x00BF0CC0 | 复用既有画布适配代码 |

数字或显示模式变化时将 shadow index 置为 -1，驱动原函数重新获取干净阴影并合成。数字和阴影都未变化时保留原生跳过逻辑。分钟/秒数位置切换、10→9、到期清字均不复用已绘制的数字。

每次合成新画布；共享 WZ 资源只读。缓存 10 张数字图片，不缓存 Buff 的 COM 图层；显示状态表与券倒计时元数据在地图初始化/销毁时清空，场景内最多保留 128 个键。新画布的额外引用在 InsertCanvas 后释放。原生接口或数字资源失败时保留原生阴影，不退回悬浮覆盖层；失败日志受已有 Buff 日志开关控制。

## 倍率券生命周期

服务端在登录完成倍率初始化、地图完成切换、复活及背包券变更时同步 `0x100A`：`uint16 count`，每项为 `int32 itemId + int64 remainingMillis`，`-1` 表示永久。客户端以收到快照时的单调时钟递减，避免本机时间与服务器时间差；完整快照会清理已移除的券。格式错误、重复 ID 或非倍率券 ID 不替换当前快照。

该包仅为原生券图标提供数字，不创建独立图标或覆盖图层；图标仍由原生 GIVE_BUFF 管理。额外使用 64 位时长是为了正确显示超过原生 32 位毫秒上限（约 24.8 天）的券。普通 Buff 不受此元数据影响。

死亡和回城复活的清理保留倍率券，普通技能/药水照常清理；换线缓存里的券不按旧的 WZ 占位时长恢复，而由登录末尾从完整背包重建。加载背包不再逐张券触发异步倍率更新。有效券选择沿用倍率计算结果，刷新显示不会重复乘倍率。同 ID 多张券以最后一张到期时间显示；移出、过期或不在生效时段时，沿用现有倍率更新机制撤销。

每次登录在 SET_FIELD 后都发送完整的补图标快照，即使角色没有 Buff 也发送空列表。否则同一客户端进程返回登录界面后，旧会话缓存的药水图标可能被重新补画。倍率券 `0x100A` 在独立分支消费，只更新倒计时元数据，不覆盖补图标列表，也不进入原生未知封包处理。

Canvas.dll 的 DrawRectangle 使用 0x00FFFFFF 作为透明擦除标记；颜色 0 是零 alpha 混合，不会初始化画布。该行为已通过本地 Canvas.dll +9B8C/+9BE2 汇编与实际像素验证。字体先按原生大小合成，再整体缩放，仅重叠一列外描边以保护数字 1。

安装前核对更新函数序言和 CALL 字节。原有梦境/孵化的 InsertCanvas hook 保留；本模块通过原地址调用既有 hook 链。

## 离线验证

在 DLL 仓库运行：

~~~powershell
./tests/BuffCountdownTest.ps1
./tests/StackedBuffIconsTest.ps1
~~~

新测试使用本地 PCOM.dll/Canvas.dll 及 MapleLib 从当前 Basic.img 只读导出的数字 PNG；替代游戏的函数、图层和 factory 指针槽位，不启动 BeiDou.exe。覆盖：

- 真实像素合成、透明背景保留、共享源图片不被修改；
- 10→9 清底、分钟/秒数转换、长时 Buff、过期/无期限；
- 倍率券实际剩余时间、永久券、30 天时长、到期、快照替换/截断/重复 ID，以及普通限时物品的区分；
- 阴影帧不变但数字变化时刷新、同一秒不重复构建；
- 专注层数变化、新图层重建与地图切换缓存清理；
- 原有叠加图标首次登录、换图、清理、延迟恢复流程。
- 同进程重登收到空快照时清理旧图标，倍率券封包被独立消费且不清空普通补图标列表。

## 实机验收

使用同步到 BeiDou-Client/ijl15.dll 的 Release|x86 产物：

1. 同时使用技能 Buff 与药水，观察原图标、阴影、倒计时是否一起显示。
2. 在倒计时显示时换线，确认图标隐藏期间没有单独留下数字；返回后数字跟随对应图标。
3. 观察 60 秒附近、10→9 和到期，确认位置切换正确、无叠字。
4. 测试专注 1→5→0 层，确认层数及时更新与图标一同消失。
5. 如有多个分辨率，检查右上角排列；本实现使用画布局部坐标，不估算屏幕坐标。
6. 同时持有经验券和掉率券，核对背包到期时间；重登、换线、死亡回城与原地复活后，两个图标和剩余时间应恢复。移出或过期后应撤销对应图标和加成。

离线测试和编译不能代替游戏内换线、资源管理器加载及原生图层最终显隐验证；实机结果由用户确认。
