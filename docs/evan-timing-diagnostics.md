# 龙神施法时序诊断

2026-09-21：用户反馈魔龙分身及多个增益技能整体拖沓，尚不能区分前摇、后摇或伤害显示延迟，明确要求增加日志。本次不再调整动作资源或游戏时序。

默认开启，设置启动客户端进程的环境变量 `BEIDOU_EVAN_TIMING_LOG=0` 可关闭。输出复用 `BeiDou-Client/logs/ijl15-trace-<session>.log`，前缀 `event=evan_timing`，最多 512 条/进程，达到上限后输出一次限制提示；重启开启新会话。沿用现有 Trace 文件 8MiB 上限和既有日志目录清理机制，不新增无限增长文件。不记录账号、密码、封包正文、逐帧数据或扫描内存。日志只在技能阶段或动作状态变化时写入，不逐帧写盘，也不强制刷盘。

实现位于 `EvanTimingDiagnostics.h`，在 EvanRuntime 安装完成后独立安装诊断 detour；诊断安装失败会撤销已安装的诊断 detour，不改游戏技能逻辑。攻击入口 0095571F（ret 10h）、增益入口 0096D399（ret 1Ch）、人物 PrepareAction 00453AD1（3 参数）、CUser::Update 00930B27（与既有 ChairCompatibility 共用原生函数，以 detour 链保留其功能）。前三处校验原始入口签名。

## 字段

每条包含 UTC 时间、进程/线程、技能 ID、cast 序号、进入技能函数以来的 elapsedMs。

| phase | a | b | c |
| --- | --- | --- | --- |
| skill_entry | 当前人物 one-time action | 旧动作总时长 | 人物技能动作字段 |
| prepare_begin / prepare_end | 本次攻速参数 | 当前 one-time action | 动作总时长 |
| skill_return | 原函数返回值 | 当前 one-time action | 动作总时长 |
| illusion_timing | 上次动作时长 | 本次重算时长 | 攻速 |
| illusion_hit_schedule | 负延迟帧合计 | 全部帧合计 | 计划命中等待时间 |
| illusion_hit_queued | 段索引（从 0 开始） | 本段附加间隔 | 入队时距计划命中的剩余毫秒（游戏时钟） |
| action_clear_observed | one-time action（负值表示清除） | 动作总时长 | 人物技能动作字段 |
| superseded | 后续技能 ID | 当前 action | 0 |
| observation_timeout | 当前 action | 动作总时长 | 人物技能动作字段 |

Update 只观察当前施法的同一个人物、同一游戏线程，在动作清除时记录一次；超过 15 秒输出观察超时。人物离开地图或未再进入该更新入口时，可能没有清除事件；缺少事件不能解释为持续锁定。

`skill_entry` 是已进入技能函数，不是物理按键时刻；`illusion_hit_schedule` 是计算值，不是已经出现数字；`action_clear_observed` 是人物动作状态清除，不能证明所有移动限制解除。本次没有记录服务端增益真正生效或本地数字绘制事件，不能把计划值当作实测。若现有事件无法区分问题，再基于该会话添加必要的后续探针。

## 验证与用户复现

### 首次实测与记录修正

本机会话 `20260920-181841081Z-pid16392`（北京时间 2026-09-21 02:18～02:19），只读扫描该 Trace 完整 71768 字节，末行完整。日志达到 512 条上限，因此不代表后续测试技能均已覆盖。

- 魔法狂暴 22141002、自然力重置 22121001 各一次成功施放，人物动作清除均为进入后 1891ms。
- 冒险岛勇士 22171000 一次成功施放，578ms 清除。
- 魔龙分身 22171002 七次成功施放，其中六次捕获清除，范围 1625～1656ms；最后一次因上限没有清除记录。攻速参数 3，计划命中等待 948ms。这不是实际数字出现时间。
- 成功调用的准备/返回耗时 0～16ms。大量重复调用在人物动作未清除期间返回 0，说明技能衔接受动作状态阻挡；不能将这些调用当作成功施法。

首次日志错误地只读取普通动作 bank 的时长，`prepare_end/skill_return` 中的 720、2000 不代表正在播放的技能时长。现已按原生规则，在 one-time action 存在时读取 +0x5DC 的对应 bank。已测得的 elapsedMs、状态清除和魔龙分身独立计算值不受该日志字段错误影响。

重复的同技能、仍处于动作锁定的尝试现按 250ms 采样，合并数量记录为 `repeated_attempts` 的 a 字段；解锁后的调用立即记录。所有原游戏调用仍执行，不做输入节流。此次只修正日志，不改变游戏技能时序。

`tests/EvanTimingDiagnosticsTest.ps1` 用模拟原函数验证攻击/增益及准备前后事件、保留原调用/返回、非龙神过滤、100 次更新不写日志、清除事件和记录上限。`tests/EvanBlazeDispatchTest.ps1` 验证原生补丁签名及魔龙分身计算。DLL 使用 Release|x86 构建；这些检查不等于已经捕获真实游戏时序。

安装后由用户重启游戏，任选两三个明显迟钝的增益技能与魔龙分身：先站立单次使用，随后尝试施放后立即移动/接技能；记下技能名和大致时间即可。用户反馈前不自动操作客户端或轮询日志。后续读取遵循 workspace tools/log-query 的增量 refresh、search/grep 流程。
