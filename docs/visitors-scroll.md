# 外星访客战甲强化拖放兼容

## 范围与依据

`ezorsia/VisitorsScroll.cpp` 只补 GMS083 的外星访客强化材料拖放与 247/249 白名单双击保护，不计算成功率、升级次数、IUC、变形或期限，不修改资源、装备实例和服务端协议。依据 2026-10-22 的 083 静态反汇编与当前离线测试；尚未实机验收。

- 材料：`2046215–2046218`、`2046400–2046403`、`2471000`、`2490000–2490003`。
- 装备：`1003115–1003119`、`1052277–1052281`、`1072449–1072453`、`1082277–1082281`。
- 必须同时命中两侧 ID 白名单，并通过原 PCOM ResMan 读取双方 `info/enchantCategory == 2`。字段不存在、类型不正确、资源读取异常或管理器未初始化均拒绝；不将任意 category=2 资源自动加入白名单。
- Consume 路径为 `Item/Consume/%04d.img/%08d/info/enchantCategory`；装备使用 `Character/{Cap,Longcoat,Shoes,Glove}/%08d.img/info/enchantCategory`。
- 其他材料直接调用原 `004F5497`，不改普通卷轴、白卷、现金锤、装备配对或其他升级 UI 的全局行为。白名单材料对非白名单装备拒绝，不继续沿用 20462/20464 的错误部位推导。

## 原生路径与补丁

基线：ImageBase `00400000`，PE timestamp `4B7C15C9`，SizeOfImage `00A94000`；取证 EXE SHA-256 为 `6C4FC608E5B44708D19F07D5B88729126539E919D0B79035DA76610158F355C2`。

`MineralBagWnd::InventoryItemDropped → 004EF140 → 004F4BB7 → 004F4E1C → 原生确认分支 → 004F4EF4 → 00A09221`。

| 写入地址 | 原字节 | 实现 |
| --- | --- | --- |
| `004F4E1C` | `E8 76 06 00 00` | 仅替换 `004F4BB7` 内的配对 CALL，cdecl 两个 itemId；普通材料回原 `004F5497` |
| `004F030A` | `E8 36 0A 00 00` | 仅替换消费栏双击路径的状态检查 CALL；从 ESI 指向的原生物品安全读取 ID，2471000/2490000–2490003 返回非零，进入原 `004EFD4C` 无使用退出；其他 ID 恢复 ECX/EDX 后尾调用 `004F0D45` |

额外只读签名检查：

| 地址 | 原字节 / 意义 |
| --- | --- |
| `004F5497` | `53 56 57 8B 7C 24 10`，原配对函数序言 |
| `004F030F` | `85 C0 0F 85 35 FA FF FF`，双击返回值检查与退出分支 |
| `004F4EF4` | `E8 28 43 51 00`，原生升级发送器调用 |
| `00A09245` | `6A 56`，原 opcode |
| `00A09261` | 连续 44 字节，sourceSlot/targetSlot/flags 各 Encode2、extra 为 Encode1，完整预期数组见源码 `dependencies` |

所有签名在任何写入前检查；任一不匹配整组不安装并记录 address/offset/expected/actual。先取得全部页面写权限，缓存刷新失败则回写两个调用点的原字节，再恢复页面保护。重复安装不叠加 Hook。

不写 `00AF34DC`：矿物包继续独占拖放 vtable。`MineralBagWnd` 的 `004EFF30`、混染的 `004EFEAD`、龙神双击装备分支和 `VisitorsMorph` 补丁均保留。全局 `004F5497` 及其另一个调用点 `0082CCC5` 不变，避免扩展未知的其他升级 UI。

## 目标规则、确认与协议

- 穿戴装备使用原装备窗口命中测试，最终发送负槽位。
- 装备栏沿用 083 **传说之灵** 原窗口选择正槽位，保持原忙碌标志、白卷复选框与完成后的窗口重置；没有新增“跨背包页直接拖到装备”能力，也不绕过原技能/目标规则。
- 保留 `004F5697` 输入条件、`00485BF7` 节流、原目标查询、现金装备确认 `SP 114F`、白卷确认 `SP F7B`；普通卷轴并非每次都弹确认框，不人为新增一个统一提示。
- 发送器 `00A09221` 完全不改：`opcode:u16=0056, tick:u32, sourceSlot:i16, targetSlot:i16, flags:i16, extra:u8`。包体 11 字节，加 opcode 共 13 字节；flags、extra 由原路径产生，不自行造值。
- 原发送器仍设置 context `+20A4` 的 pending 与 `+20A8` 的 tick；不自行减少材料/修改装备，结果仅由服务端原卷轴效果及背包更新驱动。

## 资源、期限与诊断

图标链 `005D3BD8 → 005DA83C → 005D3322` 使用原消费品资源读取。离线测试用真实 PCOM 反读全部 33 个白名单的分类、13 个材料的 `icon/iconRaw`（26 个画布），没有新增专用光标、确认框、结果素材或 IMG/WZ 改动。维持原卷轴结果处理，静态与离线验证不等于实际画面已通过。

本模块不新增“剩余期限”tooltip。保留 083 对服务端 expiration 的原生显示，不假定 `incPERIOD=2100000` 等于永久、不在 DLL 计算延期，也不引入未协商的 IUC/期限旁表。

现有 `ClientLog::Lifecycle`：安装事件 `visitors_scroll_install`；配对 `visitors_scroll_match` 每进程最多 32 条，包含材料/装备/双方类别/放行结果；双击拦截 `visitors_scroll_double_click_blocked` 最多 8 条。不记凭据，不增加逐帧或逐包日志。配对日志只表示本地校验通过，不表示服务端处理成功。

## 离线测试与实机验收

运行 `tests/VisitorsScrollTest.ps1`，测试编译为独立 x86 程序，映射磁盘 EXE 到隔离地址；不执行 EXE 入口，不启动游戏/服务端，不建立网络连接。只对测试映像的外部依赖设置桩与全局地址重定位，执行原生 `004F4BB7` 和 `00A09221`：

- 逐字节破坏两个补丁及五组依赖签名，验证拒绝安装且不产生部分写入；验证其他 Hook 的占位内容保持。
- 13×20 配对，边界 ID、非白名单目标、错误/缺失分类及资源异常；约 11 万组普通卷轴输入与原函数结果比较。
- 所有配对覆盖负槽 `-1/-5/-7/-8` 和正槽 `1/17/127`；验证完整 13 字节报文、pending/tick、原白卷确认/复选框、现金装备确认取消、输入条件、节流和空目标。
- 执行原双击 CALL/TEST/JNZ 分支，验证白名单 247/249 走原无使用退出，其他材料仍执行原状态谓词；验证日志上限。
- 使用本机 PCOM 读取现有资源，不改客户端文件。
