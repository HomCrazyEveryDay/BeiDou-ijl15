# 雇佣商店 72 小时倒计时

## 原生证据（GMS083 / BeiDou.exe）

本轮静态核对的 `BeiDou.exe` SHA-256：`6c4fc608e5b44708d19f07d5b88729126539e919d0b79035da76610158f355c2`。以下补丁点均逐字节匹配；未启动客户端。

- `0x00518AFC` 调用 `CInPacket::Decode4` (`0x00406629`)，读取店主名称后的一个 32 位已营业毫秒值，写入窗口 `+0x788`；`+0x78C` 记录收到房间包时的 `GetTickCount()`。紧随其后的 `0x00518B0A` 才读首次开店标记 byte。
- `0x00518314` 是倒计时绘制路径。`0x00518326–0x00518341` 计算 `(elapsedMs + GetTickCount() - receiveTick) / 60000`。
- `0x00518343` 原始字节 `BB 9F 05 00 00 6A 3C 59 2B D8`，用 1439 减去已营业分钟；`0x0051835C` 原始字节 `83 FE 17 0F 8F 90 01 00 00`，超过 23 小时则跳过绘制。
- 剩余时间使用 StringPool `3470` (`Store Closed / %02d : %02d`) 格式化，原生整数格式支持 72 和 168，无需改字体、画布或窗口资源。
- StringPool `3498` 的雇佣协议及 `ReplacementFuncs.h` 中文替换写死营业 24 小时；同字符串还有寄存后 24 小时收手续费的独立条款，不能一并替换。
- “超过营业时间关闭”消息 StringPool `3463` 位于 `0x00518E36` 的收包处理分支。倒计时绘制函数本身不发送关店请求，离线商店由服务端收摊。

## 实现

新服务端在店主房间包之前发送扩展 `0x100D / version byte 1 / hours ushort`。DLL 从已解密数据偏移 4 读取 opcode，总长度 9 字节；验证版本、长度和 1–596 小时范围，吞掉无效扩展以免进入原生分发。每次收到 SetField (`0x7D`) 重置为旧服默认 24 小时，新店或重新进入维护界面会收到最新时限。

安装时验证两个补丁点完整原始机器码，全部匹配才修改；同页只调用一次保护切换，写入后刷新指令缓存并恢复原保护。补丁把 `1439 - elapsedMinutes` 改为 `durationMinutes - elapsedMinutes`，低于零钳制为零，并移除 23 小时的上限判断。继续使用原生换算、格式化和绘制。时限由服务端控制，DLL 不改关店、交易、物品或金币逻辑。

服务端同时将旧的 `ceil(elapsedMinutes / 1440 * 1318)` 高 short 估算编码改为真实 elapsed-millisecond int；两侧配套发布。新的 DLL 可以接收未扩展的旧服房间包，但显示精度仍取决于旧服原有编码。旧 DLL 不支持新服务端扩展，不能把本变更作为服务端单独发布。

## 验证

`tests/HiredMerchantClockTest.ps1` 在隔离的 x86 测试进程映射原生字节，执行真实安装函数、实际 code cave 和原生除法/边界判断，验证 72/168 小时、24 小时后仍有剩余时间、到期归零、错误封包、换图重置、签名失败无改写以及页保护恢复。不启动或操作游戏客户端。

仍需用户实机检查店主界面排版、新店约 72:00、维护后计时连续、跨 24 小时交易和 72 小时到期收摊。后台修改时限后，下次进入店主界面更新显示；正在打开的界面不主动订阅后台配置。
