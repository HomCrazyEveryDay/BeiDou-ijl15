# OS4 Shuttle：083 原生特殊骑宠兼容

## 范围与依据

2026-10-22 实现；依据当前 `BeiDou.exe` 的反汇编、离线字节检查与 x86 钩子执行测试。支持 vehicle **1932037**，只接受 **1065 / 10001065 / 20001065 / 20011065**；不放开其他 193xxxx 或任意职业前缀。

服务器负责授予、15 天到期以及 `MONSTER_RIDING(vehicle, sourceSkill)`。DLL 不授予技能、不改期限、不改资源、不重写封包字段。资源已安装及服务器已配套是本任务的外部前提，不属于本模块离线测试结论。

## 补点与 ABI

| 地址 | 原字节 | 行为与续接 |
| --- | --- | --- |
| `0x008C4686` | `3D E1 7A 1D 00` | EAX=vehicle；1932037 转 `0x008C46A2`；其他重放 CMP，续 `0x008C468B` |
| `0x00936905` | `8B D8 8B 45 08` | EAX=job、ESI=CUser、EBP+8=vehicle；OS4 写 EBP-0x10=技能条目、ESI+0x1F4C=240，续 `0x00936B37`；其他重放两条 MOV，续 `0x0093690A` |
| `0x009678F9` | `81 FE 07 04 00 00` | **已有 VisitorsMorph Dispatch** 内追加四 ID 分支；ESI=skill、EBX=本地 user；转 `0x009691AC`，不安装第二个钩子 |
| `0x00969E6C` | `3D 8E AA 4F 00` | EAX=skill、ESI=user；OS4 进入原生特殊骑宠限制检查 `0x00969FB4`；其他重放 CMP，续 `0x00969E71` |
| `0x0096A2F3` | `3D EC 03 00 00` | 成功施放后的 EAX=真实 skill；OS4 转原生计数 `0x0096A316`，其他续 `0x0096A2F8` |
| `0x0096D8C8` | `81 FB EC 03 00 00` | 取消封包已经编码 EBX=真实 skill；OS4 转计数 `0x0096D8F0`，其他续 `0x0096D8CE` |

新补点统一写 `E9 rel32`，六字节位置尾部补 `90`。运行时目标由 DLL 装载地址决定。上下马均沿用 `user+0x31AC` 计数及 `+0x31B0` 原生时间初始化，不伪装成 1004。

职业映射列举当前支持的冒险家、GM、骑士团、战神和龙神职业；龙神 2001/2200/2210–2218 优先，未知职业返回 0。技能查找 `0x0075C755` 为 `void* __thiscall(void* skillDb,int id)`，数据库为 `*(void**)0x00BE78DC`。资源缺失输出一次日志，局部技能指针置空，让共用尾部原有空值检查停止播放，不改用 Battleship。

## 学习等级与原生限制

- `0x009675D5` 的等级查询仍经既有 Morph 包装器；OS4 不在 Morph 的八个虚拟攻击技能之中，因此调用原生等级查询。
- `0x009676AB` 的 `level <= 0` 拒绝分支不改。Dispatch 的新增分支发生在此检查之后；不允许“未学习也能骑”。
- `0x009691AC` 调原生技能条件方法，再进原有施放路线；`0x00969E6C` 补齐特殊骑宠限制入口。地图限制、互斥状态和施放失败仍由原生路线处理。
- 不修改 local/remote temp-stat、进图 decoder 或取消封包编码；保留 `(1932037, skillId)` 和真实四前缀 ID。

## 安全与验证

2026-10-24 补齐限时技能提示汉化：当前 `BeiDou.exe` 的 StringPool 5488 为 `Expiration Date` 格式，`0x008F2B36` 的技能提示调用按年、月、日、时、分传参。该文字硬编码在客户端，使用既有 `ReplacementFuncs.h` 汉化表替换为 `到期时间：2026年11月8日 01:16` 形式，保留换行、颜色标记和五个整数参数，不调整到期时间或参数顺序。此格式覆盖所有使用该原生提示的限时技能。一起补齐 5016、5214、5272、5279、5471、5570 的封印到期、时限结束、过期取消购买/交易及限时礼物提示；5016 保留原来的月、日、年传参顺序。第二吊坠的独立到期提示继续使用已有汉化。
