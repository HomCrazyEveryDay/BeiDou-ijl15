# 资源查询异常的低开销观察日志

日期：2026-10-12 开始，2026-10-13 验证。范围：玩家提供的 `logs(4).rar` 中状态栏画布为空、商城 Canvas 转换失败的后续取证。

## 依据与边界

玩家现场 dump 能确认状态栏 percent 绘制最终拿到空源画布，不能证明 `UI/StatusBar.img/number/percent` 本身损坏。原始查询 HRESULT、查询时的键名和父节点字典未完整留在 dump，无法区分缺键、已有节点值为空、延迟加载失败或后续 Canvas 接口转换失败。

本次只补日志，不新增资源重试、画布替代、跳过绘制或原生异常处理，不改 HRESULT、VARIANT、COM 引用计数及游戏分支。分析依据是玩家样本及已核对的正式发布 EXE/PCOM；本地测试不作为玩家崩溃根因证据。

这些观察点在键名和 VARIANT 清理之前执行。安装前验证 EXE 基址、PE 版本标记和全部被覆盖指令，任一不符则不写入 hook。PCOM 父节点布局只在模块版本和对象 vtable 同时匹配时解释。状态栏调用区间覆盖原生对象查询，非此范围的普通可选节点查询不采样。

## 日志与开销

沿用启动设置 `CrashDump`（配置键 `enableCrashDump`）；关闭时不安装观察点。无需开启 `CrashTrace`。启动行 `resource_lookup_config` 的 `enabled=1 installed=1` 表示本次安装成功；关闭时 `installed` 只表示安装函数接受了禁用请求，不表示 hook 在运行。

日志写入客户端 `logs/ijl15-emergency-<session>.log`，使用现有 UTC 时间、进程/线程标记及运行、连接 ID：

- `resource_lookup`：阶段、原始 HRESULT、VARIANT 类型及是否可读、实际键名/资源路径、调用位置、父对象/源对象/输出对象及 vtable。
- `resource_property`：父属性节点数量、字典桶数量、已采集节点数量和 `complete` 标志。
- `resource_child`：有界读取的子节点名、VARIANT 类型、对象指针及延迟加载指针。

正常查询只经过整数比较及分支，不写日志、不取时间、不调用 C++ 观察函数、不扫描对象、不分配内存、不取锁。异常路径保存和恢复通用寄存器、栈、LastError、x87/SSE 状态；诊断函数内部失败不替代原生返回结果。

同一阶段及调用位置仅记录首次异常，每次进程运行最多 8 组。读取最多 64 个字典桶、24 个子节点；文本最多读取 64 个 UTF-16 字符，输出最多 159 字节并转义。循环链表、不可读内存和截断都保留不完整标记。每组最多 26 行，整批结束才刷新文件；本功能最多新增 208 条异常记录及 1 条启动配置记录，达到上限后直接恢复原生流程。

异常首次记录包含有界内存读取和同步磁盘刷新，因此不是严格零成本。正常路径实测仅为隔离 CPU 微基准，不能换算成实际 FPS 保证。共享 emergency 文件还包含其他诊断模块的记录，上述数量限制仅针对本功能。

## 如何判断下一份样本

- `hr=00000001`（S_FALSE）且 `vt=0000`：对照相应父节点摘要和实际键名，优先检查查询未命中；不能仅凭此断言磁盘 IMG 缺少资源。
- `hr=00000000`（S_OK）却返回空值：若能看到同名子节点，结合其值和 `lazy` 指针判断是否为节点已存在但尚无对象；`lazy` 非零本身不证明加载失败。
- `stage=canvas_qi`、`hr=80004002`（E_NOINTERFACE）：来源对象不支持本次 Canvas 接口请求，结合来源 vtable、前序资源路径和 dump 继续追踪。
- `complete=0`、`keyRead=0` 或 `vtKnown=0`：证据不完整；不得把未采集到的内容报告为节点不存在。

父节点摘要为 `snapshot=best_effort`，没有为读取字典加游戏锁，不能视为跨线程一致性快照。BYREF 对象仅做安全的有限读取，不为诊断调用 COM 方法。总量上限、同位置去重、并发占用时跳过及进程突然退出都可能导致未捕获；没有日志不等于没有异常。

`tests/ResourceLookupDiagnosticsTest.ps1 -ClientExe <正式客户端 EXE>` 将正式 EXE 指令映射到测试地址，仅执行观察点和测试 continuation，不运行游戏入口。

已通过：禁用和版本不符不修改指令；真实指令签名安装；共享页面权限恢复；正常和异常 HRESULT 的原生分支；VARIANT 内容及原错误 IID；寄存器/栈/LastError/浮点状态；观察日志失败隔离；首次去重和 8 组上限；损坏字典、不可读 Unicode 名称及文本边界。

1000 万次选中范围内的正常查询无日志、无内存读取探针。最后一次本机微基准中位数：原流程 8.42 ns，加入观察点 9.73 ns，差值 1.31 ns/次。这是测试机测量，不代表游戏内帧率验收。

DLL 使用 `Release|x86`。本次交付从 DLL 仓库 `BeiDou` 分支基线 `a63b9c0be2d38e5b26a0c533c466d5727c4fef8c` 建立隔离目录，只加入本次诊断源码及接入；原工作区未提交的 `CharacterStatGuard`、`CopyAvailableCanvas` 及本地配置不纳入此产物，原文件保留。
