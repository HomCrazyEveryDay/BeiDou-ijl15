# 磁石失败动画崩溃

## 证据

2026-09-22 10:55:58（UTC+8），本地角色“抽象派”施放磁石后崩溃。
客户端捕获 `C0000005`，故障位于 `GR2D_DX8.DLL+0x7998`，读取地址为零；
服务端随后记录该连接 `SocketException: Connection reset`。

异常上下文已被退出过程改写，不能直接把 `.ecxr` 的线程退出栈当作原始调用栈。
dump 保留的栈内存仍有连续调用痕迹：

- `00668E27`：磁石本地命中处理，调用 `0066926E`，成功参数为 0。
- `006692C2`：调用 `00438EB6`（Catch 效果绘制）。
- `00439314`：失败分支调用 `00426BAB`，给 InsertCanvas 的画布为空。

对应客户端 EXE SHA-256：
`6c4fc608e5b44708d19f07d5b88729126539e919d0b79035da76610158f355c2`。

反汇编及 StringPool 确认：`00438EB6` 从 `Effect/BasicEff.img` 读取资源；
成功分支读取 `Catch/Success`（字符串 0xE67）并播放帧目录；失败分支读取
`Catch/Fail`（0xE68），却直接查询 IWzCanvas。当前客户端的 Fail 实际是
5 帧目录，Success 是 8 帧目录；MapleLib 反读的类型、尺寸、origin 和 delay
与服务端 `wz/Effect.wz/BasicEff.img.xml` 一致。目录不能查询成画布，随后
InsertCanvas 解引用空指针。

## 修复范围

`ClientCrashFixes.cpp` 将 `00438FCF` 的失败条件分支接到一个保持原生栈布局的
短跳板，选择 `Catch/Fail` 后进入已有成功动画加载流程，完整播放失败的 5 帧。
成功分支不变，不把失败显示成成功，也不吞异常或跳过失败提示。
安装前核对条件分支和恢复位置的指令字节，未知客户端布局拒绝安装。
启动日志以 `magnet.animation install result=1` 记录安装结果。

这是当前客户端 Fail 帧目录与 083 单画布读取器之间的兼容修复，适用于此处
验证的客户端资源组合。若换回单画布 Fail 资源，应重新评估，不应直接套用。
技能数值、目标过滤和服务端逻辑无需改变；XML/IMG 本身包含完整动画，保持原样。
成功/失败吸附效果使用的 0xFB 是正确操作码，不能因服务端枚举中 0xFD 的
SHOW_MAGNET 名称而替换；该名称与客户端实际协议不符。

## 验证与边界

- 构建 `Release|x86`，核对编译后跳板指令和原 EXE 的补丁签名。
- 对实际 EXE/DLL 指令进行 x86 仿真，成功及失败两分支均通过：资源字符串
  分别为 0xE67/0xE68，EAX、原生参数栈、临时栈指针及 SEH 状态保持一致。
- 交付时同步 `out/Release/ijl15.dll` 至本地 `BeiDou-Client/ijl15.dll` 并核对哈希。
- 用户实测：普通怪成功吸附、Boss/固定怪失败、连续施放、同图旁观角色。
  失败提示应保留，且施法者和旁观者均不应卡顿或退出。
- 2026-09-22 用户确认测试通过并授权提交推送；未逐项说明覆盖场景，
  不将该反馈扩展为所有历史同图掉线场景均已验证。

本次 dump 证实的是施法者的失败动画崩溃；同图历史掉线曾广播失败效果时
也能到达同一绘制路径，但尚未用同图实测证明所有历史症状只有这一个原因。
本地验证不等于 gz 已修复；远端发布须另行授权。本次不提交日志或 dump。
