# 混合美瞳选双色后预览崩溃

日期：2026-10-03。范围：本地 BeiDou 083 DLL。未启动、登录或操作游戏客户端，未改 IMG、服务端逻辑或数据库，未提交或发布远端。

## 证据与原因

用户在选择两种瞳色后客户端退出。08:24:53 的条件异常转储（运行 ID `afccd164f9b50b854f928b42ce79cd6e`，PID 24048）捕获了 `E_POINTER (80004003)`。

- 原生 `LoadFaceAction (00407A36)` 保存的脸型为 `0x50045337`，即基本色脸型 21303 与第二色 21203 的混合。面饰为 1012764。
- 实际抛出点 `004093F5`，返回地址 `004093FA`；该处要求脸部画布的 `origin` 为有效 `IWzVector2D`。转储中该指针为零，画布及面饰指针均存在。最近资源路径指向面饰不等于面饰是根因。
- `BlendCanvas` 设置了画布的 originX/Y，但这两个 Canvas 属性不会自动创建 WZ `origin` 子节点。原测试只校验像素与 originX/Y，漏了原生合成器使用的子节点接口。新增断言在修复前确实失败。
- 同时存在预览类型误判：`CUtilDlgEx::SetAvatar` 在 `009ACA93` 单独以 ID / 10000 判断脸型、发型、肤色，混色编码进入默认肤色分支。转储中 Avatar 的肤色与脸型均为 `0x50045337`。此前图层构建的补救把脸型设对，但无法恢复已经覆盖的肤色。

## 修复

1. 每个混合画布创建独立的 `Shape2D#Vector2D`，将对齐后的 origin 写入 WZ 子节点；坐标与画布 originX/Y 一致，不修改任何源画布或共享坐标对象。
2. 在原生美容窗口分类之前识别混色编码，按脸型／发型分类，完整编码仍保留在选项列表。原生函数只修改对应外观字段；肤色、装备及另一类外观保持原值。
3. 三个混染补丁均先检查指令签名并获取页权限，然后一起写入；失败时回滚已写入字节。普通 ID 的美容分类沿用原函数。
