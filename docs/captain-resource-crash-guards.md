# 船长玩家资源读取异常：第一版防崩溃修复

基于 2026-09-25 船长玩家附件的五次异常，按用户指定的“玩家 IMG 与当前工程一致”交付。此版防止三个已确认的空对象路径继续解引用，并补充限量诊断；尚未证明资源对象最初为何变空，也不覆盖音频后台线程那次访问异常。

## 修改范围

| 玩家现场 | 补丁入口 | 异常时行为 |
|---|---|---|
| `00401D52`，海鸥空袭 / 超级章鱼炮台的人物装扮合成 | `00401D3E` | 派生槽位字符串或其 BSTR 为空时，借用同一部件已有的装备 vslot 参与本轮排序；原始 vslot 也为空才禁用该异常部件本轮绘制 |
| `005DAE07`，宠物查询扎昆卡片 `2388023` | `005DAD7E` | 物品信息对象为空时释放当前 WZ property 引用，返回校验值 0；绕过校验值缓存，下一次允许重新查询 |
| `CANVAS+ED28`，状态栏经验值左括号 | `008DA50B` | 源画布为空时重新读取 `UI/StatusBar.img/number/Lbracket`；恢复后正常绘制，仍失败时只跳过该次括号复制 |

正常数据继续使用原生逻辑。人物部件 fallback 仅借用原始槽位，不改资源、不写入派生槽位、不增减其 BSTR 引用；但原始 vslot 比派生遮挡槽位更宽，异常时仍需观察衣物遮挡表现。补丁入口避开 `00401D52`，保留原生多槽位循环跳回目标。

物品补丁处理的是本地物品校验值计算，不制造道具，不修改服务端拾取权限、背包、距离与掉落归属检查，也不修改 005D5224 的宠物属性缓存。当前 PetLootHandler 按掉落物 OID 执行服务端校验，不以客户端这个校验值授权道具。若底层资源持续读取失败，此版不能保证该物品所有后续 UI 路径恢复。

状态栏最多持有一个 fallback canvas 的 COM 引用；原生查询恢复后释放。读取失败最多每秒重试一次。三个故障类别各最多写 8 条 `resource.guard` 事件，沿用现有 CrashReporter trace 配置与日志上限；正常帧不增加资源查询或写盘。其他异常继续交给既有崩溃捕获能力。

所有补丁校验 EXE 基址、时间戳、图像大小以及目标机器码。初始化结果记录为 `install avatar=1 item=1 statusbar=1`；签名不符的入口不写入。

## 三层影响

- DLL：修改原生读取结果异常时的执行路径，增加有限恢复与诊断。
- 服务端逻辑、WZ/XML：技能数值、攻击频率、拾取规则均未改变，不需要 Java 编译或服务端重启。
- 客户端 IMG：本轮已按相同资源基线验证可读，不修改技能动作、时装画布或图层表。校服 `1051574` 的 smap 疑点未被证明导致本次空指针，不混入本修复。

## 已完成验证

执行 `tests/ResourceReadGuardsTest.ps1`，将当前 EXE 映射到独立 x86 测试进程，运行补丁及原生槽位循环、物品校验分支。测试不运行游戏入口，不连接服务端：

- 正常槽位、空 holder、空 BSTR、合法空字符串、多个二字槽位、缺少原始 vslot；验证循环目标、显示标志、借用数据不持久化。
- 正常物品校验及缓存；空信息时禁止调用转换/缓存，校验 property / ZRef 恰好释放，保留原生异常清理状态。
- 汇编与 C++ 交界的调用参数、栈平衡及 MXCSR 保存恢复。
- 状态栏正常透传、重读成功、失败限频、后续恢复、引用释放，以及其他绘制异常继续传播。
- 使用当前 PCOM / ResMan / Namespace / Canvas 及当前 IMG，执行生产 `LoadBracket` 函数并验证返回画布尺寸。

登录请求初始化回归测试、宠物属性缓存回归测试通过。DLL `Release|x86` 构建通过；链接器有现有的 detours.pdb 缺失警告，无编译错误。

## 用户实机验证

1. 使用同步后的 `BeiDou-Client/ijl15.dll`，确认日志的三项 install 都为 1。
2. 兔兔保留原装扮，在扎昆场景重复海鸥空袭、超级章鱼炮台；观察是否闪退及披风/校服遮挡是否异常。
3. 带宠物完成扎昆，重点检查卡片掉落、宠物拾取、图鉴与背包表现。
4. 观察状态栏经验值数字和括号；如再次异常，回传本次运行的 resource.guard、崩溃报告及 dump。

这是第一版定点防崩溃补丁。客户端实机尚未验证，不能报告“已根治全部船长闪退”。不自动启动客户端、不发布或强升；强升时应使用同一构建与资源基线。
