# 客户端 DLL 模块记录

日期：2026-10-18。范围：Windows x86 的 `ijl15.dll` 模块诊断。DLL 只负责本地加密记录；上传由启动器 2.0.40 的配套变更负责，需接收服务同时升级，详见 [上传与 AI 排查](../../tools/module-audit/README.md#上传远端密钥与-ai-排查)。不自动封禁。

## 行为

- 在已有 EXE 入口钩子中、授权和 EXE 校验通过后调用 `ModuleAudit::Start()`，不在 `DllMain` 中扫描、哈希或写日志。
- 先订阅 `LdrRegisterDllNotification`，再由后台线程做启动快照。这样初始扫描期间的加载变化也会进入队列。API 不可用或注册失败时退化为快照，文件头标记 `notifications=false`。
- 回调只复制基址、映像大小、路径及加载／卸载类型到 512 槽固定队列，有效容量 511 条。回调不调用其他模块、不分配内存、不计算哈希、不写文件、不等待锁。读取和释放槽位使用 x86 原子指令。溢出记录 `coverage_gap` 及丢弃数量。
- 后台每 250ms 消费队列，每 10 秒使用 Toolhelp 完整复查一次；`ERROR_BAD_LENGTH` 有有限重试。失败记录 `snapshot_failed`，不把不完整结果当成全部模块卸载。模块数上限 2048，超过时显式报告扫描失败。
- `snapshot.dllCount` 为该次完整扫描中除主 EXE 外的模块数量，`moduleCount` 包括 EXE；通知和扫描可能观察到同一个模块，不能把事件数相加当作 DLL 数量。
- 记录名称、路径、基址、映像大小、观察时间、运行 ID，并在诊断连接上下文变化时记录连接 ID。时间是后台观察／写入时的 UTC 时间，不声称是精确的加载指令执行时间；相邻通知保留队列顺序。
- 后台收集磁盘文件大小、修改时间、SHA-256、文件版本、内嵌签名离线校验结果和证书发布者。按路径／大小／修改时间缓存，最多 2048 个文件身份、256 项待检查任务。超过容量写明 `capacity_limit`；路径截断、文件已消失或检查失败均明确标记。
- 文件检查期间不允许其他句柄写入／删除该文件；单文件不超过 256MiB，哈希循环预算 2 秒（同步磁盘调用本身无法提供严格超时）。每轮最多检查一个文件，后台线程优先级较低。网络签名检索关闭，避免拖慢游戏主线程。
- `signatureStatus=0x0` 表示本次内嵌签名离线校验通过。只含 Windows catalog 签名的系统文件可能返回 `0x800b0100`；它不表示文件就是外挂。未做在线撤销检查。`publisher` 是证书信息，即使签名校验失败也不能把它当成受信发布者。
- `origin` 只是 `game_directory`、`windows_directory` 或 `other` 的路径分类，**不是可信判定**。目前不把未知模块自动归为外挂，不阻止 DLL，不封号；可信发布包的哈希基线可在后续分析时对照。

## 加密与保留

`logs/ijl15-modules-<原有日志会话>-partN.bda` 使用 AES-256-GCM，逐条独立加密并认证文件头和序号；随机文件 ID 和随机 nonce。加密失败即停止该记录功能，在普通生命周期日志留下失败状态，绝不回退明文模块清单。普通日志只增加启用／失败状态，不复制模块路径、哈希或发布者。

每个文件最多约 4MiB，保留最近 16 个该前缀文件，约 64MiB。每次开始新段执行保留清理；仍被其他游戏进程写入的文件不会删除，因此多开时允许临时超过总量。每 5 秒批量刷盘，发生强制终止／断电时尾部可能不完整。轮转后下一次成功快照会重新输出当前模块及重新排队文件信息，避免长期运行时旧段过期导致清单永久丢失。旧版崩溃 dump、普通日志的既有行为不变。

密钥及解密用法见 [共享工具说明](../../tools/module-audit/README.md)。这版加密保护新模块日志的存储，不具备对恶意客户端的可信证明能力。

## 配置

默认启用，无需修改 `config.ini` 或启动器。继承启动环境变量：

| 变量 | 默认 | 用途 |
| --- | --- | --- |
| `BEIDOU_MODULE_AUDIT` | 启用 | 值为 `0` 时关闭记录 |
| `BEIDOU_MODULE_AUDIT_SECONDS` | `10` | 完整快照间隔；接受 `5`～`300` 秒，非法值回到默认 |

只记录当前游戏进程加载的模块。手动映射、隐藏模块、外部直接写内存和内核干预不在本版完整覆盖范围。工具看到的是普通加载器视图，不证明模块是谁注入的，也不保证能拿到原始文件名。磁盘哈希不等于已加载内存代码完整性；运行中修改已加载代码页不一定改变磁盘文件。
