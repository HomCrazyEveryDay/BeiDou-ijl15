# 钻石星辰四段跳字时序

2026-09-28：修复技能 21120006 对 BOSS 的四段伤害数字在回包集中、卡帧或目标死亡时挤在一起。

## 原因

服务端原实现将四段 SHOW_MOB_DAMAGE 按 90ms 独立定时发送，但网络和任务调度不能保证客户端的绘制间隔。通用队列每帧允许四段；死亡包还会强制画完该怪物的全部剩余数字。CMob::ShowDamage 的行号只决定纵向位置，不安排显示时间。

## 实现

- 服务端在原来的首段时点发送一次完整的目标伤害：沿用 SHOW_MOB_DAMAGE 的首段布局，附加 marker=2、总段数，以及剩余段的非负伤害和暴击标记。每个包是一轮攻击的一个目标，自然隔离连续同值攻击和多目标。
- `ComboTempestDamage` 单独保留这一组数字，收到包时保存怪物位置，下一次更新显示首段。后续每段距实际上一段显示至少 90ms，每次更新每组最多一段；卡帧后不追赶显示。
- 原生显示坐标及接口与 `CMob::ShowDamage` 一致，使用 30 像素行距，保留暴击与 MISS。延迟绘制不保存或解引用 CMob 指针，死亡后继续按保存位置画尾段，不进入通用死亡清空流程。
- 保留资源就绪重试、暴击素材回退；缓存上限 128 组、期限 2.5 秒，换图和卸载清理。截断或非法分段包直接丢弃。
- 服务端实际扣血仍在原来的动画时间加段数 × 90ms 时点，怪物已死亡或 OID 对应对象变化时不再结算。技能数值、动作和 WZ/XML/IMG 无变化。

服务端与 DLL 必须配套交付；旧 DLL 只认识扩展包的首段。当前仅同步本地客户端并重启本地服务，未部署远端。

## 验证

- `tests/ComboTempestDamageTest.ps1` 编译真实接收 Hook 与调度实现，并加载本地 EXE 的 CMob::ShowDamage 指令，在隔离地址空间对照坐标、行距、暴击、MISS 和最大整数伤害的 ABI。覆盖四段间隔、集中到包、卡帧、死亡、连续攻击、多目标、素材重试、清理、过期、计时器回绕、非法包与容量限制。
- `tests/MobDamageRemovalTest.ps1` 和 `tests/ShadowPartnerDamageSyncTest.ps1` 验证原有通用队列与影分身行为。
- Java 的 `ComboTempestDamageTest`、`PacketCreatorTest` 验证完整分段协议、扣血时点和目标隔离；`AranComboConsumptionTest` 验证前一轮连击消耗。
- DLL 使用 Release|x86 构建，安装后核对 SHA-256。尚未客户端实机验证；用户需检查 BOSS 四段是否逐段跳出，以及击杀、连续释放与旁观显示。
