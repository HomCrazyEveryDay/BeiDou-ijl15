# 影分身分段跳字修复

2026-09-27：修复标飞影分身原分身和残血追击的数字挤在一起、顺序交错。

## 原因

- 原分身收到权威回包后，在原生命中回调直接画出原分身和对应追击。三飞调用顺序为 `1,2,3,4,7,5,8,6,9`，其中 `4/7`、`5/8`、`6/9` 分别同一时点显示。
- 回包迟到时，原生分身数字被暂时抑制，随后进入通用每帧最多四段的显示队列；原实现还先放追击、后放原分身，形成 `7,4,8,5,9,6`。普通六段攻击的分身也可能集中在同一帧补出。
- `CMob::ShowDamage`（083 `006691D3..0066926D`）的行号只参与纵向坐标计算，不安排显示时间。原测试只校验最终行号和数字，未验证九段的调用顺序与时间。

## 调度

`ShadowPartnerDamageSync` 按一次攻击的一个目标保留原分身记录，而不是独立消费各段。服务端回包仅更新权威数字和追击标记，不再进入通用显示队列。

- 已及时收到回包的原分身继续在原生命中回调显示，保留原有节奏。
- 一旦原分身需要等待回包，后续原分身按行号等待，前段显示后至少间隔 120ms；未到原生命中时点的段不能提前显示。
- 全部原分身显示完毕后，追击再逐段以 120ms 间隔显示。三飞为完整的 `1..9`，双飞为 `1..6`，普通投掷为 `1..3`。
- 120ms 依据原版 `CMob::AddDamage` 的 `0066B105..0066B128`：本同步器支持的投掷技能均走默认 120ms 分支。60ms 的三个技能例外不在本同步器范围内。
- 每次更新、每个目标攻击最多显示一段；下一段以实际显示时间为起点。卡帧、批量回包不会触发同一攻击的多段追赶显示。不同攻击、不同目标保留各自时间线。
- 回包迟到的原分身及追击使用原生命中时保存的位置与紧凑行距参数。通过原生数字动画入口显示，怪物死亡移除后不再解引用旧 `CMob`，也不在死亡包到来时强制挤出所有尾段。
- 保留 2.5 秒缓存期限、128 个目标攻击容量、换图和卸载清理、暴击资源回退与 MISS。资源未就绪时保留当前段重试，后段不越过它。
- 旁观者保留既有来包作用域隔离。已在该作用域匹配全部原生分身回调的追击时间线可延续到来包返回后；未匹配完整的旁观记录仍在作用域结束时丢弃。真实旁观回调时机需要双客户端实测，本次隔离测试不证明该时机。

## 原生显示依据与验证

原版 `CMob::ShowDamage` 通过 `mob+0x120` 的位置对象调用 `00403CB7/00403CDE` 取得坐标。显示高度为 `y - 15 - line * (compact ? 15 : 30)`；正伤害调用 `00437D0F`，MISS 调用 `00438A21`。延迟显示复用这些入口与参数，不改变数字素材。

`tests/ShadowPartnerDamageSyncTest.ps1` 编译实际同步器、接收 Hook 和显示 Hook，并从当前 `BeiDou-Client/BeiDou.exe` 取出真实 `CMob::ShowDamage` 指令，在隔离地址空间中对照原生调用结果。覆盖九行、正常/紧凑行距、暴击、MISS、最大整数伤害，并验证：

- 六/九段顺序和时间、早到/迟到/部分迟到回包、卡帧不集中补画；
- 连续同值攻击与多目标隔离、重复回包、截断包、普通投掷和双飞；
- 怪物移除后仍按保存位置显示尾段，且不再读取怪物位置；
- 旁观作用域隔离、资源重试/回退、过期、换图清理、计时器回绕。

`tests/MobDamageRemovalTest.ps1` 验证其他自定义伤害的通用队列仍保留原有死亡前显示、帧预算、重试和隔离行为。

本次只修复 DLL 显示时序。服务端伤害计算、残血门槛、原有协议、技能描述/数值及 XML/IMG 均未改变，因此不需要 Java 编译、服务端重启或资源重写。DLL 使用 `Release|x86` 构建后同步本地客户端。

## 用户实机检查

1. 三飞开影分身，普通怪及 BOSS 30% 血量以上保持六段；残血追击时同列九段按顺序跳出。
2. 连续攻击、近距离投掷和回包较慢时，原分身与追击不挤在同一时点；人物出手速度、飞镖数量、实际扣血不变。
3. 击杀最后一击、暴击、MISS、双飞、普通投掷及换图无残留数字。
4. 双客户端检查旁观追击；实测时机若与既有作用域假设不符，需继续定位旁观原生命中关联，不能用本隔离测试代替。
