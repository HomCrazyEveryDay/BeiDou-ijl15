# 外星访客套装提示面板

2026-10-24。GMS 083 的装备提示框右侧补充 GMS 092 风格的套装面板。用户已实测上一版：内容/颜色/汉化基本正确，但1280×720下整组偏到左侧并抖动。本版修正坐标语义及幂等定位，已做离线原生 PCOM、隔离 EXE 映射测试；2026-10-25 复测及 Release|x86 构建通过，客户端 DLL 与构建产物 SHA-256 一致，修复后的实机行为待用户复测。开发过程不启动或操作游戏。

## 数据与边界

- `SetItemTooltip.cpp` 的 `supportedSet=5` 与服务端 `SetItemBonus.SUPPORTED={5}` 必须同步维护。不要因 IMG 存在其他套装就显示它们；新增支持须同时实现服务端效果及 DLL 对应标签/数据字段。
- 原生 ResMan 读取 `Etc/SetItemInfo.img/5`，缓存名称、四个类别、16 个成员和效果；悬停对象还必须通过 `Character/<类别>/<八位ID>.img/info/setItemID=5` 校验。基础款 `1003115/1052277/1072449/1082277` 不显示。
- 本地 `CharacterData` 的装备槽逐实例计数，重复 ID 的两个已装备实例算两件，不按类别去重；类别行由是否穿戴该类别的任意成员点亮。这与服务端 `calculate` 遍历 equipped 的成员判断一致，不把悬停的背包物品当成已装备物品。
- 展示读取 WZ 效果与装备状态；实际属性仍只由 [SetItemBonus](set-item-bonus.md) 的服务器权威快照注入。面板不修改属性、不发送封包。`RefreshPending` 完成游戏线程 `ValidateStat` 后通知面板刷新，不轮询、不创建线程。
- 显示 PDD/MDD/ACC/EVA 和 `setKey=10000` 的立方体保护说明（服务端 `VisitorQuests.wearsFullSet` / `Character.doHurtHp` 已实现）；遇到未知非零效果、非法结构或资源读取失败隐藏面板，资源错误仅记录一次。其他 GMS092 套装的通用效果展示不在本次范围。

## 样式与 092 依据

092 `0x008870F0` 构建，`0x00887D70` 排布，装备入口 `0x008886C0` 在 `0x0088B8C9` 调用。基础宽度 236，092 长文本在 320 像素处折行，并可将面板扩到该行宽度加 20；当前中文 set 5 为 236×231，行距 16；标题居中 y=8，类别行 y=35/51/67/83，白色分隔线 x=6、y=104、宽=面板宽−12。中文过宽时只向外扩宽，不裁掉名称。

标题、`2件套装效果 :`、`4件套装效果 :` 使用 Arial 12、`FF7FFF00`；成员及属性使用原装备 tooltip 的白色 `FFFFFFFF` / 灰色 `FF7B8C91` 字体。092 的效果标题始终绿色，只有属性行按阈值变白；不要把未激活标题改灰。原版标题没有 `(x/N)`，本实现也不另加计数。

类别左对齐 x=10；右侧原生装备分类标签带半角括号、右边距 10。属性标签复用经过现有汉化 hook 的 StringPool 659/660/661/662（防御力、魔法防御力、命中率、回避率），保留原冒号并追加 ` +20`。套装名和类别名来自 XML/IMG，不硬编码这些资源文本。四件效果末尾 y=209 显示“不会受到立方体内奇异力量的伤害。”，对应 092 StringPool 6197，随四件阈值变白；中文短句不需要原版英文的折行。

面板由 083 原生 `0x008F3141` 建立，与装备框相同边框参数 1、底色 `A0000040`；借用原生 canvas、font 与 layer，不添加图片、不调用完整 CUIToolTip 构造器。新层挂在主提示层 origin 下，位置跟随主框，原生清除/析构时同时释放。相同对象和装备状态重复悬停不重建层。

### 边缘与装备比较定位

先由083原生 builder 完成跟随鼠标、左右/上下避让，再读取其**最终主框位置**，不使用角色坐标、窗口局部坐标或原始悬停请求替代。普通路径的附加边界修正按092：组合宽度为主框宽+套装框宽，高度取两者最大值；`x+组合宽>视口宽` 时令 `x=视口宽−组合宽`，再将负 x 夹到0；y同理。未溢出时不移动主框。套装框始终在主框右侧、顶部对齐，不翻左、不因组合过大而隐藏。使用 `Client::m_nGameWidth/Height`，不使用 Windows 缩放后截图尺寸。

地址纠正：`00887F52/00887F74` 是 `00887D70` 的**非空比较层分支**；普通路径从 `008882B9` 开始，相同的宽高边界判断实际在 `008883CD/008883F1`，负值夹零在 `008883E0/00888400`。不能只靠反编译器参数名判断分支。

**坐标根因与转换**：IWzVector2D vtable `+20/+28` 的 get_x/get_y 返回包含父层 origin 的引擎绝对坐标，**不是**子层相对坐标；`+90 RelMove` 设置相对当前父原点的位置，不是增加一个位移。`+60 get_origin` 返回带引用的 VARIANT，`+64 put_origin` 设置父向量。主提示框的父层来自 `CWndMan`（单例 `00BEC20C`）的 `+DC` UI原点，getter `0048BBA5`；`008F33A3/008F33E2` 取该原点并设置给主框。该UI原点在 `009E2E85/8B/95` 移至 `(-400,-300)`，现有 `Client.cpp` 改成 `(-W/2,-H/2)`。真实PCOM离线验证：父原点 `(-640,-360)`、子层 RelMove `(1000,200)`，get_x/y 得到 `(360,-160)`。

本版计算 `屏幕坐标=层绝对坐标−UI原点绝对坐标`；写回为 `RelMove目标=目标屏幕坐标+UI原点绝对坐标−实际父层绝对坐标`。读取真实UI原点和实际父层，不猜半屏值，不解除原生父子关系。上一版把 get_x/y 当相对/屏幕坐标，重复把UI原点减入，正是向左/上累积漂移的根因；原测试替身也错误地只返回局部值，本版已纠正，并用真实PCOM向量覆盖转换。

**稳定性**：每个面板保存原生最终位置基准及上次修正后的位置。层位置仍等于上次结果时继续使用原生基准；检测到原生移动或新建层后重新捕获。装备计数重绘继承该基准；不会先把主框移回原位再重新修正。目标没有变化时不调用 RelMove。普通路径在装备 builder 返回后执行；比较期间延迟到 `008EBA5B` 完成其最后一次移动后执行。已核对公共 wrapper、三个直接装备调用者及四个比较调用者的返回尾部，未发现后续再次移动该tooltip的路径；CUIToolTip段的定位在MakeLayer和比较函数中，没有发现需另外hook的每帧定位入口。鼠标坐标变化会再次进入原生builder，不变则缓存返回；不新增逐帧hook或位置轮询。

**比较框**：083 `008EBA5B` 创建第一装备层A和第二主层B，B.origin=A；横排相对 `(-Bw,0)`、竖排 `(0,-Bh)`。本版等原生排完后读取两层的屏幕坐标，保留其顺序和相对间距；套装S放在两装备框最右边、与B顶部对齐，三框只作同一个必要平移。竖排通常仍是S紧邻B右侧，横排避免覆盖A。这按本轮“保留083原生位置、必要时整体避让”的要求，**替代上一版092特殊比较分支的重新排列**；不声称特殊比较排布1:1。092 builder还维护 `owner+14` 的额外层及 `0088C25F` 重排，083同偏移是悬停x，没有等价布局，不能直接移植。

例：1280×720、原生主框260×360、套装236×231。原生最终 `(1000,200)` → 主框 `(784,200)`、套装 `(1044,200)`，整组刚好贴右边；原生 `(400,180)` 保持不动，套装 `(660,180)`。原生MakeLayer使用W−1/H−1边界，因此原生已把底部主框放在y=359时，本模块不会擅自改成360。普通高分辨率及横/竖比较均有连续100次调用、零冗余移动断言。

## 安全安装及 ABI

| 地址 | 原字节 | ABI / 用途 |
| --- | --- | --- |
| `008E8252` | `B8 96 45 AD 00` | thiscall，18 个 DWORD 栈参数，RET 48；公共装备 builder 后绘制 |
| `008E6E23` | `56 8B F1 57 33 FF` | thiscall，无栈参数；ClearToolTip 前释放副层 |
| `008EBA5B` | `B8 5C 49 AD 00` | thiscall，6 个 DWORD，RET 18；比较框重定位后刷新 |

写入 `E9 rel32`，六字节处末尾补 NOP；trampoline 原样执行完整指令后返回。18 DWORD 中的原生 ZRef 按原栈字转发，不构造额外 C++ ZRef 所有者。主装备 wrapper `008F5B20` 的共享路径以及直接 builder 调用都覆盖；背包、装备栏、商店/仓库/交易的最终显示仍须实测。析构 `008E6BA3` 已调用清除函数，无需重复 hook。

安装验证 PE 基线、全部补点与帧/装备读取/UI原点getter依赖原字节，不匹配整组拒绝并记录一次。`0048BBA5` 新增只读依赖检查（`55 8B EC 51 8B 81 DC 00 00 00`），没有新增hook。写入前生成 RX trampoline；写入后刷新指令缓存、恢复页面保护。保护或刷新失败回滚原字节，恢复失败不报告安装成功；若操作系统持续拒绝回滚，保留 trampoline 避免悬空跳转，模块保持禁用。

现有 account-share `008EE273`、第二吊坠 `008F1F7F/008F1FC6`、MainPetInventoryMark、HighIdFacePreview、衣柜预览未占用这三个入口。不要再使用另一 detour 覆盖同一入口。

## 汉化和验证

服务端 `wz-zh-CN/Etc.wz/SetItemInfo.img.xml` 是从 `wz` 复制的全文件 overlay，仅修改 set 5 五个 string。其他套装、ItemID、completeCount、Effect、setKey 不变；服务器 loader 只读取支持套装的 ItemID/Effect，不读取显示名称。客户端实际 IMG 原有 set 3/1/2/5，不要误认为只有 set 5，更不要用服务端全文件替换客户端结构。

使用 workspace `tools/xml-img-patcher` 导出实际 IMG、生成精确五字段 diff，`batch --dry-run`、`batch` 后 `verify` 与完整反读比较；批处理提供全 overlay 作为 full XML，实际只应用 diff。此次产物留在 `.tmp/codex-visitors/set-tooltip/patched/Data/Etc/SetItemInfo.img`，未写客户端目录。审核后安装时应关闭客户端并同时安装 XML 对应 IMG 和 Release DLL。

`tests/SetItemTooltipTest.ps1` 默认使用上述暂存 IMG，产物全在 `.tmp/codex-visitors/set-tooltip/tests`；也可传 `-OutputDirectory` 和 `-PatchedImage`。测试只在隔离进程映射 EXE 数据，加载客户端 PCOM 库读取复制到暂存目录的资源，绝不启动 BeiDou.exe 或服务端。

测试覆盖原字节逐字节拒绝、七处保护故障回滚、RX 恢复、18/6 栈字转发、真实 PCOM WZ/字体/canvas/向量、实际 native ClearToolTip 和UI原点getter、0–4件高亮及新译文、重复实例、白名单、基础款、异线程抑制、换角色与引用释放。定位覆盖1280×720左/中/右/底部、精确贴边、负坐标、超宽超高不隐藏、100次悬停与刷新不调用RelMove、格内移动重新构建、计数重绘保留基准、同一层被原生重定位、非居中UI原点、多级父层、面板变矮恢复原生基准。比较替身构造UI原点→A→B→S图，get_x/y递归返回绝对值；覆盖横/竖、缓存命中、原生根层移动、重绘和清除。`content-0.bmp` 至 `content-4.bmp` 是离线内容绘制，frame/layer仍为替身；真实PCOM向量测试另行验证getter/origin/RelMove语义，不能代替游戏图形线程的无闪烁验收。

实机检查：0/1件全部属性灰；2/3件物防/魔防白；4件再点亮命中/回避和保护说明；每件对应类别由灰转白。悬停背包和已装备成员应依据同一套本地装备状态。商店/仓库/交易、基础款无副框、切换/关闭窗口和换角色继续回归。定位重点：

- 1280×720，道具栏最右、角色最左：悬停整组仍在道具栏附近，必要时刚好贴右边；绝不跳到屏幕最左，移动角色不能改变tooltip基准。
- 道具栏左侧/中间：与不带套装的同尺寸普通装备对照，未溢出时主框原位置不变，副框右侧顶部对齐。
- 鼠标在同一格子内移动、停止悬停、穿脱装备刷新：不来回跳、不持续漂移、不闪烁；上下/左右边缘重复测试。
- 比较框横排/竖排均保持原生两装备的相对排布，套装在最右侧并与主框顶部对齐；右/下边只作必要整体避让，关闭后无残留。
- 组合超出整个视口才夹零，不主动隐藏副框，允许自然裁切；分别测试800×600和1280×720。截图的Windows缩放比例不参与游戏坐标计算。

本版无抖动/无闪烁的实机结论仍待用户复测，不能仅凭离线断言宣称完成视觉验收。
