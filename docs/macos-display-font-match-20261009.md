## 字体的实测差异

Mac 最初将宋体/微软雅黑统一替换为苹方，后续 DLL 又强制灰度抗锯齿。对于 v83 的 12/14 像素字形，这改变了笔画和加粗效果。不能将“有灰度边缘”直接等同于“匹配 Windows”。

从本机 Windows 11 虚拟机 `C:\Windows\Fonts` 读取 `simsun.ttc`、`msyh.ttc`、`msyhbd.ttc`，用于当前用户的本地 Wine 环境，不提交或分发这些字体。新独立进程的字体 name 表确认实际选择宋体/微软雅黑，不再指向苹方。

`WineFontCanvasTest` 使用完全相同的 PCOM/Canvas、6 行文字、12/14 像素、普通/加粗及颜色，分别在原生 Windows 与 Wine 11.18 中绘制。Windows 基线 6491 个全不透明像素和 5 个半透明背景像素；Wine 使用真实字体并保留原请求时为 6491 个全不透明像素。560×160 共 89600 像素仅 5 个像素不同，位于 y=1、x=148..152（不在文字区域），最大 RGB 差值 1；文字区域一致。

PNG 与测量证据位于 workspace `exports/macos/display-20261009/`。`windows-vs-wine-original-font.png` 是相同字号的实际渲染对比；`name-scale-comparison.png` 含人工统一显示尺寸，只用于解释截图尺度，不能作为实时游戏效果。
