# 衣柜预览关闭后的图层退场

日期：2026-10-18。用户反馈前一版“调整销毁顺序 + 隐藏裁剪树”仍有错位人物残影。本次不调整预览坐标，不改角色操作、搭配、服务端或资源。

用户后续明确：残影只闪一下就消失。这更符合关闭过程中短暂暴露子层的表现，不能据此认定为持续对象泄漏。

## 核对与证据

- 本机 BeiDou.exe 的 `CUserPreview` 析构 004B2401 经 0092E1B3 进入 `CAvatar` 析构 0045011C；后者在 00450177 调用图层 `put_overlay` 解开父层，再依次 Release 图层与坐标对象。004B24EC 会清空 BED5A4，可在原生释放返回后判断析构是否走到这一位置，不访问已释放内存。
- 原 `WardrobeClip::SetVisible(false)` 仅通过 overlay 祖先链决定是否跳过绘制。原生解除 overlay 后，该层不再属于裁剪树；移除裁剪根也会撤销这道隐藏检查。它没有关闭子层本身的原生可见性。
- 独立进程加载客户端原版 PCOM/Gr2D_DX8，以真实像素复现：隐藏树后，保留子层引用并清空 overlay，子层重新出现。此证据确认旧门控的生命周期缺口；未自动操作游戏，不能将其表述为已完成用户场景实机验收。
- 对用户反馈时正在运行的客户端，仅做限定范围的对象关系读取：预览 CUser 的 ZRef 计数为 1，物理空间 singleton 已还原到地图，预览 singleton 在调用外为空。没有证据支持“角色一直因额外 ZRef 而无法析构”。读取结果和汇编放在 workspace `exports/wardrobe-preview-ownership-20261018/`，不提交进程样本。

## 修改

新增 `WardrobeClip::RetireTree`，在释放物理空间与 CUserPreview 之前执行：

1. 关闭已有绘制门控，在原生图层注册表锁内收集属于私有预览根的图层，临时 AddRef 保证退场期间对象有效。
2. 先把全部收集层的原生 `visible` 设为 0，再解除每层 `origin` 和 `overlay`。即使动画仍暂时引用其中一层，脱离父链也不会恢复可见；双向坐标/父层引用可以释放。
3. 释放临时引用，然后按商城顺序释放物理空间、角色，最后清理裁剪根和窗口引用。没有永久保存的旧图层或逐帧对象缓存。

图层注册表布局只对已经校验时间戳 4B7C13FD、镜像大小 40000 的本机 Gr2D_DX8 启用；递归锁入口增加字节校验。采用原生锁并在 SEH finally 中解锁。遍历有上限，发生错误沿用现有失败隔离，不继续暴露部分销毁对象。遍历和 COM 操作只在关闭时发生，正常帧路径不增加扫描或引用操作。

关闭时向现有可配置、限量诊断 trace 记录 `retired_layers` 和 `user_destroyed`。后者来自原生析构对 singleton 的清空，不读取已释放地址；该记录不等同于整个游戏所有动画资源已经释放的证明。
