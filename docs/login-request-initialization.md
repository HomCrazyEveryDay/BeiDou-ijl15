# 登录对象的延迟创建请求初始化

日志站点的5份线上 `004181D8` first-chance 报告保留了相同原始栈：
`00618F89 → 009E45F5 → 009F6368`。`009E4547` 是窗口重绘；
窗口虚表 `AF766C`、Draw `00618EB4` 对应骑士团外观编辑窗口。
`0061828B` 从 CLogin 的 `+244/+268 + part*4` 取得空外观数组，
加4后把地址4传入 ZXString 复制函数，在 `004181D8` 读取失败。
本机测试 crash 不作为本结论依据。

原生 CLogin 构造函数 `005F3C59` 清零阶段、职业和外观数组，
却未初始化 `+238/+23C` 两个延迟创建窗口请求字段。
更新函数 `005F4D70` 在 pending 非零、request=1 时进入外观窗口分支，
没有先检查创建阶段；默认职业0选中骑士团。
离线执行原生构造、分派和名称读取指令，用1/1残值可复现同址读4；
构造后清零两个字段则不误建窗口。线上文本未保存这些字段，
因此这是已验证的初始化缺陷修复，不宣称56份同址fatal全部已定因或解决。

## 最小补丁

沿用 ClientCrashFixes 的安装入口和 Detours，仅 hook CLogin 构造函数。
原生构造正常返回后写入两个 DWORD 的0，保留原生返回值和异常传播。
不修改公共字符串复制函数、不吞异常，不在更新或阶段切换时重置请求；
正常创建角色后续写入的请求仍可生效。安装前检查 EXE 基址、PE timestamp、
SizeOfImage 与10字节原始入口签名，不匹配则不安装。
现有崩溃 trace 记录一次 `login.request initialization install result=1/0`。

没有 Java、WZ/XML 或客户端 IMG 变更：问题在 EXE 对象状态初始化，
不涉及服务端技能/协议或资源字段。

## 验证

- `tests/LoginRequestInitializationTest.ps1`：提取生产 hook 编译 x86 测试，
  验证多种零/脏内存、仅指定8字节被额外修改、调用次数、返回值和异常传播。
- 离线原生指令验证覆盖误请求、清零后不误请求，以及后续合法请求与非空选项。
  仿真不运行图形、网络或完整游戏 UI，不能代替实机验证。
- Release|x86 构建；关闭本地客户端后同步 DLL 并核对 SHA256。

用户实测：反复进入游戏并正常返回登录，再重新登录；正常创建四个职业
（冒险家、骑士团、战神、龙神）的名字/男女/外观选择及取消返回；
随后按原方式测试船长。修复返回登录时的二次闪退不等于解决最初的网络断线。
