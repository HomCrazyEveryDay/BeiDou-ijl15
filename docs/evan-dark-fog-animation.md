# 黑暗迷雾动作兼容补齐

技能 22181002 的原版 action 为 darkFog。当前 Skill/2218.img 已有施法和命中特效，Skill/Dragon/2218.img 已有 34 帧龙动画，但 Character/00002000.img 缺少人物动作，083 原生人物和龙动作表也没有注册 darkFog。

StringPool 5496 的 infinityExplosion 为现有 22xx 技能不再引用的原型名称。其原生读取点 004A5CAC（人物）和 004A9B97（龙）都已对照客户端机器码核实。本次沿用既有动作注册 hook，将这个表项注册为 darkFog，保留技能原名、原始特效与技能 ID。

人物动作从已验证的 GMS084 Character/00002000.img 增量合并，源 SHA-256：A175EE36D44972777A71C51F61D047F63B9EFF976B3CA81263D65AECA565E5E1。保留全部六帧的 action、frame、delay、move；基础姿态引用均存在。同步服务端 Character XML。客户端 IMG 从 139501 增至 139889 字节，无关结构和像素不变，二进制反读通过。

GMS084 原版和当前 1～30 级均无 attackCount 字段，服务端 StatEffect 默认按 1 段处理。多阶段动画不代表两段伤害；动作补齐不修改段数、伤害或范围。

后续按用户要求，将原版各等级固定 20 秒的冷却改为 1 级 20 秒、30 级 4 秒，中间按 `20 - round(16 * (level - 1) / 29)` 取整数秒近似线性下降（每级减少 0～1 秒）。同步 Skill/2218.img 的 cooltime、服务端 Skill XML 和各等级技能说明。服务端直接读取 cooltime，无需改 Java；更新资源后重启本地服务加载。灵魂之石仍保持 600 秒实际冷却，描述沿用已有技能的“冷却时间10分钟”格式。

验证：原版来源哈希、原生注册调用点、原型名称无技能引用、六帧动作及基础姿态引用检查通过；Release|x86 构建通过；EvanBlazeDispatchTest 通过（既有技能分派与魔龙分身时序回归，不替代本技能实测）。客户端关闭后同步 DLL/IMG，核对构建与安装 DLL 的 SHA-256。待用户重开客户端，验证黑暗迷雾左右朝向的起手、完整龙动画、命中效果和一段伤害，以及龙推力、火焰轮回归。
