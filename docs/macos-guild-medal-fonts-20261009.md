# Wine 家族／勋章名牌字体

用户确认字符集修正后聊天和列表改善，仍反馈头顶家族名、勋章名未达到预期。此轮保留已验证的 Arial 字符集匹配及 `csmt=0`，只处理名牌路径。

## 证据

会话 `20261009-050814627Z-pid396` 的普通 Arial 均已正确匹配 Arial；唯一仍匹配 Arial Unicode MS 的请求名为“蹈框”，12 像素、常规字重、默认质量。原始 ANSI 字节为 `B5 B8 BF F2`，按 CP949 为 `돋움`（Dotum），按中文 ACP936 则得到“蹈框”。

该字节来自原生字符串池 1662，不是聊天内容。`005F0334` 名牌合成函数在 tag=1006 的字体分支，于 `005F0891` 压入 1662，按 12 像素调用字体 Create；对应勋章资源路径为字符串池 1305 `UI/NameTag.img/medal/%d`。在本机 Windows 上用同一请求测得实际回退宋体，name 表哈希 `7493D6BB`；Wine 却回退 Arial Unicode MS（`BD52E5AB`）。

tag=1004/1005 的家族／联盟标签走 `005F0F98` 分支，使用字体名 Arial、12 像素、白色、样式 BA（粗体+抗锯齿）。其字体名生成 CALL 位于 `005F0FE2`，目标 `00406292`，字体 ID 在 `005F0FD1` 为 5527。此前全局 Arial 保持正常匹配，不适合为了该标签再全局改变 Arial。

## 改动范围

- Wine 的 original 字体模式中，将精确的旧 ANSI 名 `B5 B8 BF F2` 及其 CP936 对应宽字符串映射到 SimSun。只匹配观察到的请求，不全局替换所有未知字体，也不改 WZ/IMG 或字符串池。
- 同一模式下，仅重定向名牌分支的 `005F0FE2` CALL，使用客户端自身 `00406301` 构造 SimSun 的 `_bstr_t`。后续原生 Create 包装器仍消费该引用，避免跨 CRT 分配／释放；字号、颜色、样式、文本测量与绘制继续走原流程。
- 安装前校验原 CALL 五字节和字体 ID 指令；失败不盲改。页面保护恢复，写入或恢复失败时回滚原调用。原生 Windows、smooth 模式不安装此调用补丁。
- 不改正常聊天／列表字体，不改变技能或资源，不调大所有文字。

## 验证边界

- Release|x86 构建和父进程授权检查通过。
- Windows 数据路径回归通过。Wine 测试覆盖精确旧字体名替换、普通 Arial/Tahoma 保持、传入 LOGFONT 不变。
- 隔离可执行页重放真实五字节 CALL 和两个栈参数：错误字体 ID 拒绝安装且指令不变，正确安装后连续 100 次保留返回对象、栈平衡和一次本机构造调用，页面权限恢复。构造器以测试替身验证接口与所有权路径，没有运行整个游戏初始化。
- 实际 PCOM/Canvas 渲染确认旧字体请求改为 SimSun，常规及粗体样本可绘制。离线字号、颜色和字重保持，但不能据此保证两种名牌在实机中都已改善。Windows 与 Wine 的默认平滑输出仍有差别，不宣称逐像素一致。
- 对比及日志位于 workspace `exports/macos/nametag-font-20261009/`。

用户确认关闭后，已检查游戏、启动器和退出监视器均退出且 DLL 无占用，备份并同步新构建到客户端。源码产物与 `BeiDou-Client/ijl15.dll` 的 SHA-256 均为 `9719db9f2cd61141f94321ae4569015822caeee2ab4af49a25c7b60ec0c6d8f2`；旧版本哈希 `12cb283e08abde283b5206bb973da99b2d244f785be37d5ee314e22ebea8c949`，备份路径与交付时间记录在该目录 `validation.json`。

尚未自动启动或操作游戏，实机需分别验收家族名和勋章名，不能将一项通过当作两项均通过。未提交、未推送。
