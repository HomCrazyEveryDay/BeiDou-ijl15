# 护送怪物梯绳动作（083）

实现：`ezorsia/VisitorsMobClimb.cpp/.h`；与 `VisitorsMorph`、`VisitorsScroll` 相邻注册。
本功能仅补齐服务端权威移动的观察者动作回放，不移植 092 本地 controller、mode 6、导航或附着物理。
不 hook `0x66B599`，不修改 owner vtable，不改 Mob IMG、地图坐标或原有 40 个动作的含义。

## 服务端契约

`MOVE_MONSTER` 外层头部的 action/skill 字段不变。以下值只放在移动片段的 stance 字段，不能写到头部 action：

| 资源动作 | 私有动作索引 | stance（facing=0 / 1） |
| --- | --- | --- |
| rope | 40 | `0x50 / 0x51`（80 / 81） |
| ladder | 41 | `0x52 / 0x53`（82 / 83） |

移动片段仍为原生绝对片段 type 0，little-endian：

```text
type:u8=0, x:i16, y:i16, vx:i16, vy:i16, fh:u16, stance:u8, duration:u16
```

垂直段 `fh=0, vx=0`，上行 `vy<0`、下行 `vy>0`；最低位只表示左右朝向，与上下移动无关。
具体 rope/ladder 必须由真实梯绳类型确定，不能仅以路线 attr=1 推断。地面阶段继续使用 `2/3, 4/5, 6/7` 等原生 stance。
**spawn 包保留原生 stance**；晚入观察者通过后续 type 0 移动快照获得当前爬行动作。这是本次双方约定，优先于早期研究稿的扩展 spawn 建议。
不要将这四个值发送给没有本功能的客户端。服务端仍负责路线、坐标、速度、进出段和全体观察者广播；DLL 不给予玩家 controller。

## 初始化与名称寿命

支持固定基址 `0x400000` 的当前 x86 083 EXE：PE timestamp `0x4B7C15C9`、SizeOfImage `0xA94000`。
离线基线 SHA-256：`6C4FC608E5B44708D19F07D5B88729126539E919D0B79035DA76610158F355C2`。
地址均为该基线 VA。本模块沿用 Visitors 的固定基址限制；不同基址/版本明确拒绝，不声称支持任意重定位 EXE。

1. 进程入口注册时，先校验全部九处原字节，确认原表尚未开始初始化，仅安装 `0x4A6C05` 的初始化入口转发。
2. 原生初始化函数完整执行并返回后，再确认全部 40 项非空，重新核对八处运行期补丁，然后复制名字。
3. DLL 私有表为 42 个 4-byte 原生名称对象。前 40 项经 `0x405210` 增加原生 Data 引用计数；新增两项经 `0x403382` 构造原生宽字符名称。
4. 使用客户端 `0xA606AE` 注册退出清理，逆序经 `0x403394` 释放引用。既不把 `wchar_t*` 冒充名称对象，也不使用 DLL CRT 的 `_bstr_t` 分配器来释放客户端对象。
5. 创建/注册失败释放已取得的引用；运行期补丁拒绝后仅在所有字节均已回滚时立即释放名字，避免极端保护 API 失败留下的指令引用失效表。已登记的退出清理始终保留。

不写 `0xBEC4C8` 的 40 项，也不在 `0xBEC568` 处追加；原表的原生析构仍只处理原有 40 项。
迟安装可能已有 40 槽的存活 CMob，因此发现原表已初始化时拒绝安装，不做不安全热启用。
签名不符时整组拒绝，失败原因只记一次；修改前获取保护，完成后 FlushInstructionCache 并恢复原保护。
保护申请失败或 flush 失败会回滚；保护恢复失败重试，仍失败则尝试整组回滚，并记录恢复/回滚失败而不是宣称激活成功。

## 补丁与 ABI

`T` 表示 DLL 私有 `actionNames` 的实际地址；`LE32(x)` 为小端 DWORD；`REL32(H,A)=LE32(H-A-5)`。
DLL 可重定位，因此跳转和表地址字节在运行期生成，不能把某次 DLL 装载地址硬编码到报告或 EXE。

| VA | 原字节 | 新字节 | 用途 |
| --- | --- | --- | --- |
| `0x4A6C05` | `B8 C4 24 A8 00` | `E9 REL32(Initialize,0x4A6C05)` | 原生名称初始化后激活 |
| `0x67F4C9` | `BE C8 C4 BE 00` | `E9 REL32(TemplateLoop,0x67F4C9)` | 失效可用性旁表，令 ESI=T，续接 `0x67F4CE` |
| `0x67F5CB` | `81 FE 68 C5 BE 00` | `81 FE LE32(T+0xA8)` | 模板循环排他终点 42 项 |
| `0x40C901` | `8D 04 B5 C8 C4 BE 00` | `8D 04 B5 LE32(T)` | 实际帧名称 `T[ESI]` |
| `0x662300` | `6A 28` | `6A 2A` | 每 mob 分配 42 个列表 |
| `0x664985` | `81 FE 20 03 00 00` | `81 FE 48 03 00 00` | 清空循环从 800 增至 840 bytes |
| `0x664DAF` | `83 FF 28` | `83 FF 2A` | 帧总时长查询索引上界 |
| `0x664D42` | `8B 54 24 08 85 D2` | `E9 REL32(Decode,0x664D42) 90` | raw→资源动作 |
| `0x671AFF` | `55 8B EC 56 8D 45 08` | `E9 REL32(Normalize,0x671AFF) 90 90` | raw 归一化 |

- `0x4A6C05`：无栈参数的原生初始化函数。转发重放 `MOV EAX,SEH_descriptor`，跳到 `0x4A6C0A`，保留完整 SEH 初始化/清理。后置激活保存并恢复通用寄存器与 flags。
- `0x67F4C9`：函数内接缝。保存通用寄存器/flags 调失效 helper，然后仅按原指令约定替换 ESI，原模板计数器和智能指针参数不动。
- `0x664D42`：`int __thiscall(CMob*, unsigned raw, unsigned* facingOut)`，ECX=this，栈两个参数，`ret 8`。hook 用 `__fastcall(this, ignoredEDX, raw, facingOut)`，原前六字节重放后续接 `0x664D48`。
- `0x671AFF`：`unsigned __thiscall(CMob*, unsigned raw)`，ECX=this，`ret 4`。hook 用 `__fastcall(this, ignoredEDX, raw)`，重放完整前七字节后续接 `0x671B06`。
- `0x671929`：实际返回 EAX 0/1 的 `int __thiscall(CMob*, int index)`，`ret 4`；不覆盖入口，复用原懒加载路径。
- `0x40C831`：`CActionMan` 为 ECX，栈 `templateId, actionIndex, targetList`；原资源/link/UOL、图片、origin、delay 管线保持不变。
- 名称复制 `0x405210` 与构造 `0x403382`：ECX=目标 4-byte 对象，栈一个源对象地址/宽字符串指针，`ret 4`；析构 `0x403394`：ECX=对象，无栈参数；客户端 atexit `0xA606AE` 为 cdecl，一个回调参数。

## 帧可用性与回退

仅识别恰好 `0x50–0x53`，非这些值的 raw（包括负数哨兵和高位数值）原样进入原函数。
读取有效模板完全遵循原生规则：CMob `+0x2A4` 非零且 `+0x18C` 非空时使用变形模板，否则使用 `+0x188`。
确认 `+0x434` 动态数组头 count 至少为 42 后，才允许访问新增槽。

- 旁表最多 256 个模板，键为模板指针和原生解密模板 ID；rope/ladder 分别存未知、探测中、有帧、无帧。
- 无帧结果按模板缓存；有帧模板的不同 mob 仍各自经原生 `0x671929` 懒加载自身列表。已加载列表只检查 count，不每帧读取 WZ。
- 模板动作加载循环令旁表世代失效；变形按当前真实模板重新查键。原生变形链 `0x66D820 → 0x66496F` 清空列表，现已清空全部 42 项。
- 不按 `9420075–9420077` 白名单硬放行；以当前模板及原生 link 解析所得实际帧为准，不以 XML 是否存在动作名称代替。
- 新动作缺帧或可选加载抛 C++ 资源异常时，回退到 `6 | facing`，再复用原生 air/jump→stand/fly 可用性回退；可选加载异常时清理部分列表。归一化回退自身抛资源异常时返回 air raw，不向外传播这次新增查询的异常。
- 缺帧诊断每类动作最多一条。原生普通 raw 的行为和异常不吞掉。

这是新增可选动作的容错，不保证一个连 jump/stand/fly 等原生动作都损坏的模板能够被原生播放链安全渲染。
旁表失效不是 WZ 在线热重载实现；修改运行中的原资源仍需遵循原客户端资源/模板生命周期。

## 其他索引访问审计

对基线 EXE 的可执行节扫描动作表区间 DWORD 引用，共 49 处：40 项原生注册，当前模板首尾与帧名查询，原表析构，邻接表/前表边界，以及 `0x67FD99` 从 `0xBEC4F8` 起的原生 attack 子表访问。
后者通过 `0x529EB1` 的原生模板攻击序号调用，与爬行动作 raw 无关；保留原表及原索引，不移动 attack 子表。
`0xBEC568` 起的相邻表（包括 `0x40BAAC` 查询）及 `0x4A8D7A` 前一表终点不改。

确认的 CMob `+0x434` 访问有十一处指令：

| 指令 VA | 处理 |
| --- | --- |
| `0x6622FA` | 原数组构造，唯一分配调用 `0x662308 → 0x673070`；修改其 count 即可 |
| `0x66487E` | 固定 stand/index 1 访问，无需改 |
| `0x664975` | 原清空循环，补丁将界限扩至 `0x348` |
| `0x6649B2` | 动作播放，`index*0x14`，无额外 40 项常量 |
| `0x664DB4` | 时长查询，已将前置上界扩至 42 |
| `0x666251` | 动画更新，`index*0x14`，保留 |
| `0x671932 / 0x67196E / 0x671982` | 懒加载/非空判断，`index*0x14`，保留 |
| `0x7A5A62` | CMob 主代码段外的当前帧访问，同样 `index*0x14`，已加入离线执行测试 |
| `0xAA0FF2` | 构造异常清理：取 `[EBP-0x10]+0x434`，经 `0x6722D4` 尾跳到 count 驱动的 `0x673032`；保留并加入离线执行测试 |

`0x673070` 构造、`0x673032` 析构均使用数组头 count，不另写死 40；CMob 布局不扩大，每 mob 仅多 40 bytes 列表存储。
`0x40C831` 全局动作缓存键为 `(templateId << 8) | index`，40/41 仍在低八位内，无需扩大键。
其余直接调用点 `0x529D57 / 0x8678D7` 继续使用原生动作，`0x664DF7 / 0x67197D` 通过同一个已扩展名称查表点。
扫描中的其他 `+0x434` 包括别的对象字段、安全整数校验、字符串缓冲区和指令位移，不是新增 CMob 列表。
