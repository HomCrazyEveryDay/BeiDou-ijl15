# Wine 小字号界面文字修正（2026-10-09）

用户在恢复 100% 显示比例后确认整体正确，仍指出家族名、聊天对象“对所有人”和左上角地图名存在问题。本次处理这几条字体路径；此前 125% 方案已失败，不再采用。

## 定位

- 家族名：此前日志已确认 SimSun、12 像素、700 字重、质量 4。只替换字体家族未解决观感问题。原生名牌 Canvas 格式为 1（ARGB4444）。
- 地图名：CUIMiniMap 在 `00856161`、`00856222` 创建白字及阴影字体，家族名来自 StringPool 5527（Arial），12 像素，样式来自 1411（BA，粗体抗锯齿）。
- “对所有人”：本地汉化 StringPool 786，由 CCtrlComboBox 绘制，并非背景图片中的文字。CUIStatusBar 在 `008D370F` 设置字体编号 34；`0098A707` 的编号 34 分支 `0098BD0E` 创建 Arial 11 像素、白色、普通字重。编号 0 对应相同颜色和字重的 Arial 12 像素。

独立 Wine prefix 的对照表明，关闭 Wine 模拟粗体平滑会改变小字号宋体，却不能一并解决中文链接字体及 11 像素聊天对象文字。该注册表实验没有应用到实际游戏 prefix。

## 实现

- 仅 Wine 的 original 字体模式，对 Arial、Tahoma、SimSun 的 11/12 像素、700 字重、ANTIALIASED_QUALITY 请求改用 NONANTIALIASED_QUALITY，保留字体、字号、字重和颜色。普通字重、默认质量、较大字号及其他字体不在规则内。
- 单独将 CUIStatusBar 聊天对象控件的字体编号 34 改为 0，使用 12 像素普通文字。校验原六字节指令，只改字体编号立即数一个字节；字号调整没有应用到全局字体缓存或普通聊天正文。
- UI 字体补丁仅在 Wine original 模式安装；原生 Windows 不安装。保留已有字符集和名牌字体匹配修正。
- 不修改 DPI、资源、启动器或实际 prefix 的字体注册表。诊断字体日志仍默认关闭。

## 验证及限制

- Release|x86 构建及父进程校验通过，Windows 与 Wine ACP936 兼容性回归通过。
- 隔离可执行页重放聊天对象原指令与补丁：原指令选择 34，修改后连续 100 次选择 0，栈平衡，其他字节不变，错误指令拒绝修改，页面保护恢复。家族字体调用重放测试继续通过。
- 使用实际 PCOM/Canvas 在 Wine 中绘制，普通文字对照的五行（默认质量粗体、普通字重、较大字号、11 像素普通字重）像素差异均为 0；12 像素粗体 AA 行确实改变。Tahoma 中文样本无像素变化，不能据此声称所有字体均已改善。
- “对所有人”离线对照中，12 像素实际字形占 47×12 像素，可放入原 80×20 控件；11 像素样本占 42×10。最终位置和控件背景效果仍需实机检查。
- 导出文件位于 workspace `exports/macos/small-ui-fonts-20261009/`。`format1-*` 对照使用与实际家族名牌相同的 Canvas 格式；其他字体对照不等同于整场游戏截图。Windows 虚拟机的 Arial 样本缺少部分中文字形，不将其整图差异用作质量结论。
- 相同字体文件、固定文本和格式 1 的宋体 12 像素 BA 样本，相对原生 Windows 的不同像素数由 1487 降为 10；11 像素 BA 由 1015 降为 361。其他四行未改变。这证明该固定样本改善，不代表全界面逐像素一致。

离线测试通过不代表游戏内三处均已验收。交付记录、DLL 哈希及备份路径见同目录 `validation.json`，最终由用户重开客户端检查。未自动启动、登录或操作游戏。
