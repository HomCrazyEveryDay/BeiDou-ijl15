# NPC 对话关闭后的方向键焦点恢复（2026-10-13）

> 2026-10-14 更新：首次交付的 DLL 随后被证实会在内存池探针初始化时崩溃，发生在 NPC 焦点修复安装之前。现已保留本页焦点修复并补上[启动时序修复](pool-guard-startup-crash-20261014.md)，当次配套 DLL 的 SHA-256 为 `48671ACDD37D4EC9E5B51F9CE3AC4E90B9FA5275E7D4F4945B4CED48E6250743`。下文首次构建和备份信息仅作历史记录，不应将已知有启动故障的旧 DLL 作为交付或回退版本。

## 现象和范围

用户确认：普通 NPC 对话关闭后，原生方向键 ↑↓←→ 不能立即移动，需要再点击一次画面。不是自定义 WASD 重绑定问题。

本次修复只改变 DLL 中普通对话 `CUtilDlgEx::SetRet` 的成功关闭出口。服务端任务状态、动作解锁封包、WZ/XML 和客户端 IMG 不受该焦点切换影响，无须修改或重启服务端。没有修改 `MovementKeyHook` 或输入法补丁。

## 本机 EXE 证据

分析对象 `BeiDou-Client/BeiDou.exe`：SHA-256 `6C4FC608E5B44708D19F07D5B88729126539E919D0B79035DA76610158F355C2`，PE 时间戳 `4B7C15C9`、映像大小 `A94000`。地址由本机 EXE 反汇编确认。

- `CUtilDlgEx` 构造函数 `009A32CD` 设置主虚表 `00B3E100`，`+34` 的关闭方法为 `009AB50A`。
- 输入合法或取消后到达 `009AB8EF`，写入返回值和完成标志；仅当窗口仍创建时，`009AB908` 调用原生 `CWnd::DestroyWnd(009E00AF)`。输入校验失败不经过这个调用点。
- `DestroyWnd` 在注销绘图窗口后通过 `009E0166` 调用 `CWndMan::RemoveWnd(009E3454)`。后者清除原焦点，并在 `009E3517..009E3531` 从剩余窗口列表选择窗口激活。这条路径可以把键盘交给另一个 CWnd。
- `CWndMan +88` 保存键盘目标；`+74` 是模态输入列表数量。`009E33FC` 登记模态输入，`009E3454` 移除；`009E42B7` 在模态列表非空时优先按该列表处理鼠标目标。
- 游戏默认输入目标是 `CWndMan +4`，其 `OnKey(009E2F05)` 把按键交给当前场景。鼠标按下路径在 `009E3F42` 通过 `SetFocus(009E3264)` 切换输入目标；普通按键派发只在原焦点为空时尝试回到默认目标，已有其他 CWnd 焦点时不会自动转交。

上述证据解释了可以出现“关闭对话后按键仍被其他界面接收，点击画面后恢复”的路径。尚未捕获用户当次游戏运行中具体哪个窗口持有焦点，不能把离线构造的窗口身份视为用户现场取证。

## 修复

`NpcDialogFocusFix` 只替换 `009AB908` 的调用，先完整执行原生窗口销毁，再在以下条件全部满足时用原生 `SetFocus` 将键盘目标切回 `CWndMan +4`：

- 当前有本地角色和场景；
- 销毁前后的窗口管理器、本地角色和场景相同；
- 模态列表已经为空。

不读取已销毁对话对象，不改变窗口列表，不模拟鼠标点击，不清空服务端动作锁，不接管全局键盘或全局焦点函数。嵌套对话、校验失败、重复关闭和登录/商城上下文保持原流程。安装前检查 EXE 标识及目标指令，失败时不打补丁；安装和前 8 次恢复记录到现有 `npc.focus` 事件。
