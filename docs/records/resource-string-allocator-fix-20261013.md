# 资源字符串分配器错配：复现与修复

日期：2026-10-13。继续核对[射手村集中掉线调查](henesys-boss-disconnect-investigation-20261013.md)中的字符串生命周期线索。证据来自已有玩家 dump、正式 1.0.34 组件、本地源码及隔离 x86 测试；没有启动/登录游戏，没有修改生产或发布客户端。

## 已确认的缺陷

PCOM 在游戏进程内通过主程序公开的 `ZtlTaskMemAllocImp`、`ZtlTaskMemReallocImp`、`ZtlTaskMemFreeImp` 使用游戏内存池。资源接口返回的 `VT_BSTR` 和 UOL 文本仍有四字节长度前缀，但底层存储不是 `SysAllocString` 分配的 Automation 内存。

此前 `MixedDyeResources::Value` 的析构/移动赋值使用 `VariantClear`，UOL 返回文本使用 `SysFreeString`。因此组件返回字符串会被交给错误的释放器。`CheckCategory` 正常读取 `info/islot=Hr`、`Names` 正常枚举 `islot` 就可以进入该缺陷，不需要损坏资源或异常输入。旧 `VariantCopy` 还会为交还原生调用方的字符串创建系统分配器副本，存在反方向的所有权错配。

影响路径包括混染/混瞳资源构建、普通发型 40902/43206/44092 的绳梯兼容构建，以及复用同一 `Value`/枚举逻辑的 3015759 椅子图像引用处理。客户端会读取其他同屏角色的外观，因此触发条件不限于本机角色使用相应外观。是否在某次具体闪退前执行过这些路径，仍需运行证据。

## 复现证据与事故关联边界

本地证据目录：workspace `_diagnostics/zhumeng-20261012-221516/`。

| 隔离实验 | 结果 |

| 游戏原内存池 + 原 `CheckCategory` | `C0000374` 堆损坏，退出码 -1073740940 |

上述复现记录为 `bstr-proof-*.txt` 和 `bstr-path-results.json`。对照只修改清理配对，未更换正常输入。

已有 11 份 dump 中，3 份保存了 PCOM 的分配器槽位，均为 `009F2503 / 009F2525 / 009F2514`，包括 10-12 当晚 pid87648 的现场。其余未保存该页，不能解释为未启用游戏分配器。详见 `bstr-runtime-callbacks.json`。

这些样本加载的 ijl15 模块标记为 `6ACA6C26`，与正式 1.0.34 一致；正式 DLL SHA-256 为 `b5c44ac3d93af19b95c4eda48a62461a3f79ba50cd2021acd904fb0d1764550b`。前序核对已确认其中存在该外观处理路径。PCOM 实验文件与正式清单 SHA-256 一致：`917181e24f3b152302f9f93adf4ac3e13baf086a68224d258f47df5bb3862cf1`。

**结论：分配器错配是已复现的代码缺陷，玩家进程也确实采用该分配器组合；尚未证明它是当晚全部 193 个异常运行的共同源头。** 现有 dump 没有最早坏值和写入者，也没有证明每个故障运行都执行过上述外观/椅子路径。实验的 `C0000374` 不等于把现场的 E_POINTER、800401F8、80030002、80070057 或 Canvas 空指针直接判定为同一根因。

## 修复内容

- 新增 `ResourceVariant.h`，按主程序公开导出选择资源输出字符串的分配/释放器，无游戏导出的独立组件测试仍使用 Automation 分配器。DLL 不修改 PCOM 的回调或游戏分配器。
- `Value` 析构、移动赋值、资源遍历和 UOL 返回字符串改为配套清理；UOL 使用作用域所有权，构造路径时抛异常也能释放。
- 混染和椅子向原生调用方复制返回值时，BSTR 副本使用资源分配器；保留长度和内嵌 NUL，处理空 BSTR 与分配失败。接口指针仍按原 COM 引用计数处理，BYREF 保持借用语义。
- 倒计时、现代装备及资源防崩的三个通用资源查询清理点同步使用同一规则。这些点正常应返回接口，其同类型字符串风险也得到处理，但没有据此声称三者正常路径已单独复现崩溃。
- 调用方自己通过 `SysAllocString` 创建的输入键名继续用 `SysFreeString`；不混淆输入和返回值所有权。
- 服务端逻辑及 XML/IMG 不涉及变更：缺陷在客户端资源返回值的内存管理，不是资源内容或游戏规则。

## 验证

新增可重复执行的 `tests/ResourceVariantTest.ps1`：编译无导出与有主程序分配器导出两个独立程序。第二个程序公开与游戏相同的接口，并使用独立堆；由真实 PCOM 自行发现并使用导出，不需要映射游戏代码、修改组件回调或启动客户端。

两个模式各完成 10,000 轮真实 Property 类别读取、枚举、复制及字符串清理。主程序分配器模式记录 40,014 次合法释放，循环后的活跃分配数不增长，堆校验通过；另外验证了内嵌 NUL、空字符串指针、移动覆盖、自复制、分配失败、COM 引用计数及 BYREF 借用。

以下现有测试也通过：

- `MixedDyeTest.ps1`：真实发型/脸型、非对称颜色、兼容动作与 18 个特殊发型类别。
- `MixedDyeHookTest.ps1`：资源入口、椅子 30 帧像素、原生返回约定、外观缓存淘汰及失败回退。
- `ModernEquipmentCompatibilityTest.ps1`：装备资源、接口引用、宠物动作、2,000 次外观加载释放。
- `ResourceReadGuardsTest.ps1`：画布边界、资源重取、引用计数与有界重试。
- `BuffCountdownTest.ps1`：真实画布合成、数字刷新、状态生命周期。

后五项仍在各自既有独立测试环境中运行，不能等同于游戏原内存池的实机场景压力测试。

`ezorsia.sln /p:Configuration=Release /p:Platform=x86` 编译成功，构建内置的启动器父进程策略检查通过。构建有原第三方 detours 库缺 PDB 的 LNK4099 警告；日志保存为 `resource-variant-build.log`。
