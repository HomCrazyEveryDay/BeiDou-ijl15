# PCOM 退出内存池生命周期修复

2026-10-12。范围：退出阶段 `004031FE` 晚到释放；游戏内掉线和 Canvas 根因仍单独排查。本记录仅表示代码修复与专项验证，未发布、未完成完整游戏实机验收。

生产运行已出现 `cleanup.begin → cleanup.end entries=0 → pool.end` 后再次 `004031FE`，说明提前清空 List 仍不能覆盖全部晚到持有者。独立测试执行真实 `PcInitModule`、List 清理、原生池销毁、`PcTermModule`，复现了模块路径字符串在同一指令访问已销毁内存。

修复只接管 `00796D45` 注册的池 CRT 析构回调 `00796D51`，让池保持有效至进程结束；PCOM 和其他 WZ DLL 的后续释放仍使用有效池。正常 Alloc/Realloc/Free、PCOM 析构与异常传播保持原行为。Windows 最终回收进程内存。

影响与边界：

- 退出最后阶段不再提前整批释放 backing blocks，也不提前清理仍有其他持有者的 List。运行期间没有新增对象保留策略；代价仅为原有池内存在进程终止前继续占用。
- 补丁检查 EXE/PCOM 版本、目标指令、分配器回调及池状态；不匹配时拒绝安装。
- 退出诊断每进程至多一条；不吞掉无关释放异常，不通过强制终止掩盖错误。
- 不将所有生产 `004031FE` 样本都认定为同一个字符串；本修复处理的是池早于依赖 DLL 销毁的生命周期缺陷。

验证入口：`tests/PcomExitFixTest.ps1`。八组包含原版故障、旧清表方案反例、guard/Windows heap 正常释放、PcTermModule 晚到释放、未初始化 List、无关异常传播。测试只在独立进程执行原生组件和分配器，不启动或登录游戏。

2026-10-12 复验：八组全部通过；`Release|x86` 构建与构建附带的 LauncherParentPolicyTest 通过。构建仍有既有代码的收缩转换、内联汇编及 Detours PDB 缺失警告，本次 PCOM 源码没有新增编译警告。

提交配套 DLL 使用干净 `BeiDou` 主分支加本次 PCOM 变更单独构建 `Release|x86`，不包含尚未提交的 Canvas 或属性包保护。客户端需关闭后同步并核对 SHA-256。正常退出、登录前退出和异常断线后退出仍需用户实机验收；测试通过不等于生产故障全部关闭。
