# 龙神骑乘兼容排查（2026-09-23）

## 已确认的证据

角色 ffff 使用技能后，20260923-132212753Z-pid17532 的 DLL 日志记录：收到骑乘模型 1902040、来源 1004；后续 CUser 骑乘状态为 1902040；AvatarLayerBuild 收到该模型与动作 0/2/35。用户反馈仍只有人物坐下，龙保持跟随形态。这些日志不能证明骑乘图片已经加载。

对照本地 BeiDou.exe (083) 与 GMS_v84.1_L.exe (084)：

- 083 的 407757（AvatarLayerBuild）把参数 4 的 0xD0 字节外观数组复制到临时缓冲，参数 8 是骑乘模型。
- 083 的 4138BE 与 084 的 41434D 均在模型类别为 190 时从外观数组索引 18 取骑兽、19 取龙鞍。索引 18 为零会跳过骑兽和鞍子的图片加载。
- 当前服务端 EvanMount.model 以龙鞍选择模型；角色 -18 没有骑兽，因此只有 buff 模型不足以加载图片。这是本地服务端约定与原生加载器之间的缺口，不能说成 084 原版不需要骑兽槽。

## 本次修复

AvatarLayerBuild 仅对 1902040/41/42 与对应 1912033/34/35 的有效组合创建独立外观副本，将模型写入副本索引 18，再调用原生图层加载器。原外观、背包、任务状态和资源坐标不变。普通骑宠与不匹配龙鞍不进入兼容分支。

移除了错误标为临时状态解析器的 9671C4 来源转换 hook：该地址实际属于技能使用判断，不能用于证明 buff 解析兼容。

DLL 日志新增 `evan_mount_layers stage=appearance`，包含模型、实际送入加载器的骑兽/龙鞍槽和 prepared 标志。与之前事件诊断共享 BEIDOU_EVAN_MOUNT_LOG 开关，图层记录每进程最多 96 次。

## 仍保留的前期行为及边界

968BA0 的龙神入口兼容分支只检查龙鞍对象非空，回到 968D83；物品 ID、等级和技能有效性仍由服务端 EvanMount 检查。不能将旧测试输出里的等级边界表述为客户端入口已验证等级。服务端现有首次骑乘包来源转换仍保留，本次未修改 Java、XML/IMG。
