# OSSS 计时器分钟显示

2026-11-01：任务 51217 发放的 `4032735` 仍是原版 60 分钟限时物品，提示框标题显示为 `OSSS计时器（已过12分钟）`。名称前缀读取现有 String IMG，数字按已过的完整分钟计算，范围 0～60；普通背包中保持悬停也会自动跨分钟刷新。服务器换成 `4032736` 后保留其原生完成物品名称。

这是客户端动态显示功能。原生标题来自固定 String 名称，XML 无法根据实例期限实时改变名称，因此由 `VisitorsTimerTooltip` 接入原生标题绘制；不修改 WZ/XML/IMG、不新增阶段物品、不写物品实例，也不改变服务端的到期转换、下线作废或任务奖励。

## 时间与开销

客户端观察现有 `SET_FIELD (0x7D)` 数据末尾的八字节服务器时间；对应服务端 `PacketCreator.getCharInfo/getWarpToMap`。它与物品到期时间采用相同的 FILETIME 编码及服务器时区偏移，两者相减不依赖玩家电脑日期、时区或夏令时。收到时间后使用 `GetTickCount64` 累加经过时长，换图／换频道重新校准；登录应答清空旧时间。无有效服务器时间或无限期 GM 道具时回退原始标题。

没有新增服务器查询、封包、数据库写入或后台线程。只在背包已有计时器提示框时跟随原生 UI 更新，每 250 毫秒做一次时间比较，分钟改变才重新绘制一次。已过 60 分钟时不再重复重绘；真正换物品仍由服务器每分钟的过期检查完成，画面显示 60 分钟不代表任务已经交付。

## 原生接入与生命周期

依据实际 `BeiDou.exe`（SHA-256 `6C4FC608E5B44708D19F07D5B88729126539E919D0B79035DA76610158F355C2`）：

| 接入位置 | 用途 |
| --- | --- |
| `008F5B20` | 公共物品提示框入口，转发全部 8 个栈参数；仅在当前调用期间读取实际物品 ID 和 `+20` 到期时间 |
| `008EE57A` | 普通道具标题的 `GetItemName` 调用；仅替换 `4032735` 的返回字符串后缀，保留共享资源字符串 |
| `00B39108` → `0081E255` | 背包更新虚表，先执行原生更新，再检查计时；与主宠标记的内部调用补点共存 |
| 既有 `SetItemTooltip::ClearHook` | 清除提示框时同时取消计时刷新；DLL 初始化只有成功安装该清理入口才启用计时器模块 |

原生道具提示框只根据鼠标坐标缓存，所以跨分钟时仅使该提示框的缓存失效。刷新重新进入原生背包悬停路径，重新获取当前格子的道具，不持有旧物品、ZRef 或栈上 options 指针。关闭窗口、换角色、地图时间重新同步和清理图层时丢弃旧状态；格子已空且原生悬停直接返回时主动清除旧提示框。UI 操作只在原提示框所属线程执行。

安装先核对 PE、补点和依赖指令字节；保护修改失败会回滚所有补点。仅记录一次安装成功／失败，不逐帧或逐分钟写日志。

## 验证与实机边界

`tests/VisitorsTimerTooltipTest.ps1` 在隔离进程映射 EXE，不启动游戏。覆盖 1～60 分钟前后共 120 个边界、原生参数与补点、七处保护故障回滚、原地悬停一分钟只重绘一次、时间恢复、到期不改物品、空格与同坐标换道具、关窗口、换角色、跨线程拒绝及无限期道具回退。套装提示框及主宠标记回归同时通过。

测试中的背包事件和标题构建使用替身；实际游戏内字体、位置、无闪烁及服务器换物品仍由用户验收。重启配套客户端、通过任务取得计时器，保持鼠标悬停跨过一分钟，检查标题从 0 变成 1；移开再悬停、关包重开、正常换频道后应显示当前已过分钟。服务端和资源无需为本显示功能更新。
