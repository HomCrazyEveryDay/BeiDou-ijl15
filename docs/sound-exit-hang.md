# 游戏关闭后 BeiDou.exe 残留

2026-11-03，来源为本机真实残留进程快照、当前交付的 `Sound_DX8.dll` 反汇编及独立原生回归。现行修复在 `SoundExitFix.cpp`，由已有声音组件加载钩子安装；未启动或操作客户端进行自动验收。

## 已确认的原因

会话 `20261103-113116472Z-pid2448` 于北京时间 19:38:58 请求 `ExitProcess(0)`，窗口消失后仍残留。19:39:45 的完整快照只剩主线程 21648，调用链为 `ExitProcess → LdrShutdownProcess → SOUND_DX8 CRT finalizer → +3976 → +3F1A → +428D → +115B → Sleep(1)`。

声音工作对象 `0x0F541278` 的工作线程 ID 为 `0x4740`，停止请求字段 `+14` 为 1。原生 `+1194..+11A0` 循环等待工作线程改变该字段；Windows 在 DLL 进程退出回调前已经终止其他线程，因此这个回应不可能再到达。现场保存在 workspace `_diagnostics/exit-hang-20261103/`，包括完整 dump 和调用栈，不提交 Git。

另一次会话在 18:46:44 请求退出、18:51:17 才以退出码 1 结束。退出码本身不能证明发起结束的是哪个程序。本次已证实声音清理的卡死机制，尚未确认是哪次版本改动使声音对象存活到了 DLL 最终卸载阶段。

## 修复边界

- 核对 SOUND_DX8 的 PE 时间戳 `4B7C1425`、映像大小 `24000`、原始 CRT 注册及析构指令，再接管 `+2D6E` 注册的专用终结回调 `+2D7A`。
- 仅当 `RtlDllShutdownInProgress()` 确认进程正在最终退出时，不再运行这个进程级声音单例的析构，由操作系统回收其剩余内存和句柄。此时其他线程已经不存在，不能执行等待工作线程或获取其持有锁的清理。
- 游戏运行期间的 Stop、Release 和显式 FreeLibrary 仍执行原生清理，不改音量、解码、播放、资源或服务端。不是用强制结束进程替代正常退出，也没有取消退出/崩溃日志。
- 缺少系统查询函数或版本/指令不匹配时拒绝安装；未知版本不能视为修复已生效。运行日志 `sound_exit_fix install result=1` 表示安装成功，`native_finalizer_skipped=1` 表示实际命中最终退出保护。

## 验证与交付

`tests/SoundExitFixTest.ps1` 在独立进程加载真实 SOUND_DX8，调用其注册的 CRT 回调和原生停止等待循环，以真实线程模拟音频线程，无游戏启动、音频设备或播放操作：

1. 未修复时，ExitProcess 终止工作线程后，真实原生回调稳定卡住；测试父进程只清理自己创建的子进程。
2. 修复后同一场景正常退出，退出码为 0，确认命中最终退出保护。
3. 正常运行时仍等待存活工作线程响应，执行原生析构。
4. 显式 FreeLibrary 保留原生析构，随后同地址重载重新安装退出补丁。

四项通过。`Release|x86` 构建及附带启动器父进程策略检查通过；构建有既有 Detours PDB 缺失警告。原残留进程在用户授权结束后，普通 taskkill 失败；核对 PID、创建时间及唯一剩余线程归属后终止该线程，进程等待句柄确认已结束。

确认无 BeiDou.exe 运行后，已同步 `out/Release/ijl15.dll` 到 `BeiDou-Client/ijl15.dll`，两者 SHA-256 一致：`51AD11504BF51A9539FA15CD57B58B3BFFD3C074E0D8F1929D0662CDFF5177B7`。替换前 DLL 保存在 workspace `.tmp/sound-exit-install-20261103/ijl15.dll.before`。构建保留工作区已有的其他功能改动，未回退升降台或装备兼容修改。

真实游戏的进入地图后退出、登录界面退出以及声音播放效果仍待用户验收；不将离线结果当作完整实机验收。玩家端尚未发布。上述哈希对应保留其他本地改动的测试版；退出修复的独立提交配套产物从该源码提交构建，其哈希记录在客户端配套提交中。
