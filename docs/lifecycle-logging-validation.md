## 原始证据与缺口

PID 17524 会话记录了进图、玛瑙祝福增益和 10:00:16 地图清理，但没有退出堆栈、异常记录或 dump。不能据此把地图清理判定为崩溃。9:40 的 Windows 事件属于另一进程，不能混用。

## 本轮改动

- 保留并标明预期切换、已确认注销、进程清理和未知关闭的区别，不再将已知关闭路径静默丢弃。
- 观察所有线程的访问异常、非法指令、除零、页读取异常、不可继续异常和 C++ 异常；记录为 first chance，不宣称它们必然致命。继续返回 EXCEPTION_CONTINUE_SEARCH，不吞掉异常。
- 记录 ExitProcess 和针对本进程的 TerminateProcess 请求、调用位置与退出码，随后调用原 API；失败时保留原错误码。请求记录本身不等于进程已经退出。
- 观察 SetUnhandledExceptionFilter 的后续更换，原样转发，不阻止客户端设置自己的处理器。它可解释为何 first chance 已记录却未进入本 DLL 的 dump 处理器。
- `ijl15-emergency-<session>.log` 绕过普通日志锁，直接写入并 FlushFileBuffers，保留异常和退出的最小证据。详细堆栈及最近 32 条封包元数据仍在 lifecycle 中。
- dump 记录包含写入是否成功、Win32 错误码及路径；未处理异常入口先写应急记录。
- 发送 SPECIAL_MOVE 前只记录技能 ID、等级，不保留整包、账号或认证数据。若施法在生成封包前失败，不会有该条，不能因此认定用户没按技能。
- `[debug] enableLifecycleDiagnostics` 默认 false；本机 config.ini 已显式开启，作为此次复现诊断配置保留，不提交。没有新增持续后台轮询任务。

## 实机验收与边界

由用户重新启动客户端，进图后释放一次极光恢复，告知发生时间及窗口表现。按 session/PID 对应 emergency、lifecycle、crash 和 Windows 事件，确认实际属于异常、主动退出还是其他路径；不能只凭文件存在判定采集成功。

本轮未自动启动或操作游戏，真实复现仍待用户执行。其他进程强杀、断电、绕过被观察 API 的直接系统调用，以及部分 fail-fast/栈耗尽路径不能保证执行进程内回调；若复现仍无终止证据，下一步使用独立进程退出监视/外部调试捕获，不能把缺失记录解读为正常退出。

## 2026-09-15 资源请求与延时特效来源

ResourceProvenance.h 校验 083 EXE 版本及机器码后观察 00403A93 资源包装入口和 00444000 延时特效路径赋值位置。记录调用栈、线程/时间/序号、节点地址、原始参数、原始路径及拼接后路径副本。原始 _bstr_t 在 EBP+24，最终字符串在 EBP-10；依据 00443FC2/00444000 反汇编。资源观察不依赖技能，入队观察覆盖本次异常队列，不声称覆盖全部动画类。
